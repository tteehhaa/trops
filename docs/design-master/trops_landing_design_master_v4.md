### 2-1. 정렬 교차 리듬

배경 교차는 `.sec-surface` 클래스 하나로 통제한다(§3-1). 순서: **bg → surface →
dark → bg → surface → bg → surface → bg → surface → bg → surface → bg → surface
→ dark.** 다크는 페이지에 정확히 둘, 4(신뢰)와 15(푸터)뿐이다 —
`test/landing-order-s9.test.js` O7이 "배경이 연속인 이웃이 없다"를 센다.

### 2-2. 우선순위 (라이브가 실제로 실행한 순서)

옛 "3→4→7"(안심문구 승격 → 2층카드 → 신뢰 이미지) 대신, 라이브 코드주석이 실제로
따른 감정선은 **기(2 히어로) → 승(3 경험담) → 전(4 경고 · 5 HOW · 6 근거) →
결(7 결 CTA)**이다. 안심 문구(8)는 그 **뒤**, "누르지 않은 사람의 망설임에
답하는" risk-reversal 자리로 옮겨졌다 — 이는 옛 우선순위 1번("안심 문구를 맨
위에서 한 번")과 정반대 배치다. 옛 표를 참고하지 말 것.

🔄 **2026-08-16 A3 §2 — 상품소개(9)가 서사 밖으로 나갔다.** basis-split-s13
시점에는 상품소개가 경고(4) 바로 뒤, 서사 한가운데 있어 기승전결이 카탈로그에서
끊겼다. A3 §2는 상품소개를 안심 문구(8) **뒤**로 내리고, 그 빈자리를 HOW(5)가
경고 **직후**로 올라와 대신하게 했다 — "각성(경고) → 답(HOW) → 근거 → 결 →
안심"이 끊기지 않고 이어지고, 상품 상세는 그 서사가 끝난 뒤 읽고 싶어진 사람이
찾아보는 카탈로그가 된다. 상품 이름이 페이지 앞쪽에서 완전히 사라지지 않도록
히어로에 미니 신호(§4 C-9)를 신설해 세 탭에 앵커를 걸었다.

## 3. 디자인 토큰

### 3-1. 색 (🔴 v3에서 값이 바뀐 것 3종 — `index.html` `:root` 원문 기준)

```css
/* 잉크 — 4단계, 변경 없음 */
--ink:    #0F172A;
--ink-70: rgba(15,23,42,.70);
--ink-64: rgba(15,23,42,.64);
--ink-62: rgba(15,23,42,.62);
--muted:  #94A3B8;

/* 액센트 — 클릭 가능한 요소에만, 변경 없음 */
--accent:       #1D4ED8;
--accent-press: #1E40AF;
--accent-soft:  #EFF6FF;

/* 배경 — 3층 */
--bg:           #FFFFFF;
--surface:      #E6ECF3;   /* 🔴 v3 값 #F1F5F9(ΔL* 3.65)에서 재변경. 3.65도 교차가
                               안 잡혀 6.86으로 한 번 더 내렸다(2026-08-14) */
--surface-dark: #0F172A;   /* 변경 없음 */

/* 선 */
--line:            #E2E8F0;   /* 변경 없음. --bg 위 전용 */
--line-on-surface: #CBD5E1;   /* 🔴 신설(2026-08-14). --surface 위에서 --line은
                                  ΔL* 1.38로 사실상 안 보여 이 값을 대신 쓴다.
                                  직접 쓰지 말 것 — .sec-surface가 --line 자체를
                                  이 값으로 갈아 끼우므로 하위 규칙은 var(--line)만
                                  쓰면 된다 */

/* 경고 */
--warning: #DC2626;   /* 경고 전용. 폼 오류 메시지에만 */

/* 다크 잉크 — --surface-dark 위에서만, 3단계 */
--d-ink-primary:   #FFFFFF;                  /* 🔴 v3 값 rgba(255,255,255,.72)에서 재변경 */
--d-ink-secondary: rgba(255,255,255,.72);    /* 🔴 v3 값 .50에서 재변경 */
--d-ink-tertiary:  rgba(255,255,255,.50);    /* 🔴 v3 값 .28에서 재변경 */
--d-line:          rgba(255,255,255,.28);    /* 🔴 신설. 다크 배경 위 선(헤어라인) 전용.
                                                 텍스트로 쓰면 2.50:1로 AA 미달 —
                                                 선에만 쓸 것 */
```

**왜 v3와 다른가 — 접근성.** `index.html` `:root` 주석이 명시적으로 적어 뒀다:
v3 §3-1이 "정본 값 그대로 명명만 정식화"라고 적었지만 실제로는 와이어프레임의
4단계(#FFF / .72 / .50 / 선 .28)에서 #FFFFFF가 빠지고 선 알파(.28)가 잉크
3단계로 밀려 올라갔다. v3 값을 그대로 쓰면:

- tertiary(.28)로 찍히는 본문 7역할(신뢰 출처줄·플레이스홀더 라벨·푸터
  연락처·KAIST 표기·사업자값·면책문구)이 **2.50:1로 WCAG AA(4.5:1) 미달**
- 4 신뢰 섹션 H2가 #FFFFFF에서 .72로 내려가 옛 와이어프레임 C 블록 사양과 어긋남

그래서 라이브는 **이름은 v3를 따르고 값은 한 단계씩 올려 대비를 지켰다.** 이
문서(v4)는 그 라이브 값을 그대로 등재한다 — 더 이상 "정본과 구현이 다르다"는
상태가 아니다.


2 히어로의 리드와 CTA 사이에 상품명 3개를 나열한 한 줄. **왜 필요한가**: A3
§2가 9 상품소개(3탭 카드)를 안심 문구 뒤로 내리며, 히어로 바로 아래에서 보이던
"무엇을 파는 곳인가"가 경고·HOW·근거·결 CTA·안심 문구 다섯 섹션 뒤로 밀렸다.
이 한 줄은 그 공백을 메우는 **이름표**다 — 상품 소개가 아니라 "여기서 파는
것이 셋이고 아래에 있다"는 신호 하나다.

- 클릭하면 9 상품소개의 **해당 탭 버튼**이 선택되고 그 자리로 스크롤한다(페이지
  이동 아님). 도착지는 탭이지 패널이 아니다 — 선택되지 않은 패널은 `[hidden]`
  이라 앵커 목표가 되지 못한다
- 무게는 리드보다 아래, 마이크로카피와 같은 층(`--ink-62`) — 크기만 한 단계
  위(13.5px, 마이크로카피는 12.5px)
- `--accent`를 쓰지 않는다. 히어로에서 `--accent`를 갖는 것은 eyebrow 하나뿐이고,
  액센트가 둘이 되면 바로 아래 주 CTA(C-1)가 묻힌다
- 밑줄은 hover·focus에서만 — 기본값으로 깔면 세 이름이 나란히 밑줄져 "메뉴
  바"로 읽히고 헤더 nav와 층이 겹친다
- 구분점(`·`)은 `aria-hidden`, `--muted`(장식이라 본문 대비 하한 미적용)
- **설명을 붙이지 않는다.** 한 줄이라도 붙으면 9 상품소개와 같은 일을 두 곳에서
  하게 되고, 그것이 이 페이지가 2026-08 내내 없애 온 중복이다. 명확화는 C-2 각
  패널의 요약(`.feat-sum`)이 맡는다
- 이름 3개는 상품명 정본 그대로(`docs/copy/...v4.0.md` 어휘표) — 여기서 새
  이름을 짓지 않는다. 버튼으로 올리지 않는다(주 CTA와 위계가 같아지면 무엇을
  눌러야 하는지가 갈린다)

## 6. 🔴 색이 판정하면 안 된다 (원칙 변경 없음)

**이 제품의 핵심 원칙은 「판단하지 않는다」이다.** 대조/비교 결과에서 「다른

| 보라 | AI 신호 |

## 7. 🔴 준거법·관할 — 해소 경위 (v3의 §7 설계안은 채택되지 않음)

v3 §7은 "대조한 항목 / 대조하지 않은 항목"으로 화면을 구조적으로 분리하는
설계안을 냈고, §12에 "L-1 미결 — 제품 PRD 확인 필요"로 남겨 뒀다. **라이브는
다른 경로로 이 문제를 해소했다** — 제품 결과지 코드(`lib/precheck/nda/
result-view.ts` ⑤ 분리 항목)가 준거법·체결형식을 애초에 비교 상태 없이
"미포함"으로만 표시하도록 짜여 있어, v3가 우려한 "「다름」으로 찍히는" 상황
자체가 발생하지 않는다(라이브 코드주석, 6 근거 섹션 머리주석).

v3의 "대조하지 않은 항목" 별도 블록 UI는 랜딩·결과지 어디에도 구현되지 않았다
— 채택되지 않은 설계안으로 남는다. 4상태 체계 매핑 문제(구 L-1)는 이 경위로
**사실상 해소**된 것으로 보이나, 제품 PRD 쪽의 공식 확인 여부는 이 저장소
문서만으로는 알 수 없다(§12 미결 L-1 갱신 참조).
