## 1. 색 토큰

### 1-1. 변경분 (3줄)

```css
--accent:       #1D4ED8;   /* 주 CTA 배경, 텍스트 링크 */
--accent-press: #1E40AF;   /* 눌림·호버 상태 */
--accent-soft:  #EFF6FF;   /* eyebrow 뱃지, 강조 배경 */
```

기존 `--accent: #0F172A`를 대체한다. **이 세 줄이 이번 작업의 핵심**이고, 나머지는 이걸 전제로 따라온다.

### 1-2. 전체 토큰 (변경 없는 것 포함)

| 토큰 | 값 | 역할 | 상태 |
|---|---|---|---|
| `--ink` | `#0F172A` | 헤딩·본문 최고 대비 | 유지 |
| `--ink-70` / `--ink-64` / `--ink-62` | `rgba(15,23,42,.70/.64/.62)` | 본문 계층 | 유지 |
| `--muted` | `#94A3B8` | 캡션·비활성 | 유지 |
| `--line` | `#E2E8F0` | 구분선·테두리 | 유지 |
| `--bg` | `#FFFFFF` | 기본 배경 | 유지 |
| `--surface` | `#F8FAFC` → **`#F1F5F9`** | 섹션 교차 배경 | 변경 |
| `--surface-dark` | **`#0F172A`** | 다크 섹션 1곳 | 신설 |
| `--accent` | **`#1D4ED8`** | 주 CTA·링크 | 변경 |
| `--accent-press` | **`#1E40AF`** | 눌림 | 신설 |
| `--accent-soft` | **`#EFF6FF`** | 강조 배경 | 신설 |
| `--warning` | `#DC2626` | 경고 전용 | 유지 |

**`--surface`를 낮추는 이유**: 현행 `#F8FAFC`는 흰색과 명도차가 1.5%뿐이라 섹션 교차가 눈에 안 잡힌다. `#F1F5F9`면 3%가 되어 구분은 되면서도 얼룩져 보이지 않는다.

### 1-3. 색 사용 규칙

- 액센트는 **클릭 가능한 것에만**. 장식·아이콘·구분선에 쓰지 않는다.
- `--accent-soft`는 배경으로만. 이 위의 글자는 `--accent`를 쓴다.
- 초록·주황을 새로 도입하지 않는다. **판정 신호로 읽히기 때문**이며, 이건 미감이 아니라 「판단하지 않는다」 원칙의 문제다.

## 2. 버튼 위계 (V3)

현행은 네 개 버튼이 전부 `#0F172A` 배경에 흰 글씨라 구분이 0이다. 세 종으로 나눈다.

| 종류 | 배경 | 글자 | 테두리 | 쓰는 곳 |
|---|---|---|---|---|
| **주** | `--accent` | `#FFF` | 없음 | 페이지당 최대 2회 (히어로·마감) |
| **보조** | `transparent` | `--ink` | `1px --line` | 주 CTA 옆, 덜 중요한 행동 |
| **텍스트 링크** | 없음 | `--accent` | 없음 | 카드·섹션 내 이동 |

```css
.btn-primary   { background: var(--accent); color: #fff; }
.btn-primary:hover { background: var(--accent-press); }
.btn-secondary { background: transparent; color: var(--ink); border: 1px solid var(--line); }
.btn-secondary:hover { border-color: var(--ink-70); }
.btn-link      { color: var(--accent); background: none; border: none; }
```

**공통 사양** (현행 유지 + 1건 수정)

| 항목 | 값 | 비고 |
|---|---|---|
| 폰트 | 15.5px / 600 | 유지 |
| radius | 6px | 유지 (Anaconda 4px보다 부드럽고 Pretendard와 맞음) |
| transition | `background-color .14s, border-color .14s` | 유지 (Anaconda 0.3s보다 경쾌) |
| padding | `0 22px` → **`12px 22px`** | **수정** |

**padding 수정 이유**: 현행 세로 패딩이 0이고 높이를 부모가 강제한다. 터치 타깃 44px 확보가 부모 스타일에 종속돼 있어 깨지기 쉽다. 버튼 자체가 높이를 갖게 한다.

## 3. 타입 스케일

### 3-1. 확정 값

| 역할 | 모바일 | 데스크톱 | 굵기 | 행간 | 자간 |
|---|---|---|---|---|---|
| H1 | 36 | **40.7 → 56** | 700 | **1.18 → 1.30** | −0.035em |
| H2 | 28 | **29.6 → 40** | 700 | 1.28 | −0.030em |
| H3 | — | **28** (신설) | 600 | 1.35 | −0.025em |
| 카드 제목 | 18 | 20 | 600 | 1.35 | −0.02em |
| eyebrow | 12.5 | 12.5 | 700 | 1.5 | +0.14em |
| 리드 | 16.5 | 18 | 400 | 1.6 | 0 |
| 본문 | 16.5 | 16.5 | 400 | **1.76** | 0 |
| 캡션 | 12.5 | 12.5 | 400 | 1.7 | 0 |

**굵게 표시된 것만 바꾸면 된다.** 나머지는 현행 그대로다.

### 3-2. 왜 H1을 키우나 (V2)

379px → 925px 사이 헤딩 변화율 실측:

| | trops | anaconda |
|---|---|---|
| H1 | 36 → 40.7 (**1.13배**) | 32 → 64 (**2.0배**) |
| H2 | 28 → 29.6 (1.06배) | 28 → 48 (1.71배) |

trops 헤딩은 데스크톱에서 사실상 안 커진다. `clamp()` 상한이 낮게 잡혀 있는 것으로 보인다. **값 하나짜리 수정인데 체감 차이는 이 문서에서 가장 크다.**

```css
h1 { font-size: clamp(2rem, 4.5vw, 3.5rem); }   /* 32 → 56px */
h2 { font-size: clamp(1.75rem, 3vw, 2.5rem); }  /* 28 → 40px */
```

Anaconda의 64px까지 가지 않는 이유는 한글이 라틴보다 글자당 정보 밀도가 높아 같은 px에서 더 커 보이기 때문이다. 56px이 한글 기준 대응점이다.

### 3-3. 왜 행간만 풀고 자간은 두나 (V4)

현행 H1은 행간 1.18과 자간 −0.035em이 **둘 다 타이트**하다. 한글 헤딩에서 자간을 조이는 건 맞는 선택이지만, 행간까지 같이 조이면 두 줄 헤딩이 뭉쳐 보인다. 현행 H1이 실제로 두 줄이라 바로 드러난다.

**자간 −0.035em은 유지, 행간만 1.30으로.**

### 3-4. 반응형 규칙 (Anaconda에서 가져올 것)

Anaconda 실측에서 나온 규칙이고, 그대로 쓸 만하다.

**H1·H2만 스케일한다. 나머지는 전부 고정.**

| | 379px | 1125px |
|---|---|---|
| H3 · eyebrow · 본문 · 버튼 | 고정 | 고정 |
| 리드 | 16.5 | 18 (소폭) |
| H1 · H2 | 스케일 | 스케일 |

반응형 타입 관리 대상이 두 줄로 줄어든다.

## 4. 배경과 섹션 리듬 (V6)

현행은 배경 교차가 `#F8FAFC` 한 곳뿐이고 다크 섹션이 없어 전 페이지가 무채색 평면이다.

### 4-1. 4층 구조

```
헤더            --bg
히어로          --bg
어떻게 대조하나요  --surface        ← 교차 1
신뢰 증명       --surface-dark    ← 다크 1회
FTA 세율 조회    --bg
로드맵          --surface        ← 교차 2
마감 CTA        --bg
푸터            --surface-dark
```

**다크 섹션을 신뢰 증명 자리에 두는 이유**: 이 섹션이 신설 대상(G2)이라 기존 화면을 안 건드린다. 그리고 숫자와 근거 출처가 다크 배경에서 가장 또렷하다. Anaconda도 다크를 홈에만 쓰고 제품 페이지엔 안 쓴다 — **페이지당 1회가 상한**이다.

### 4-2. 섹션 패딩

| | 모바일 | 데스크톱 |
|---|---|---|
| 상하 | 60px | **96px** |
| 좌우 | 24px | **48px** |

Anaconda는 좌우 80px인데, 콘텐츠 폭이 1200이고 뷰포트가 넓을 때의 값이다. trops의 1200 컨테이너에는 48px이 맞다.

### 4-3. 콘텐츠 폭 (변경 없음)

현행 `1200 / 880 / 860` 3단을 유지한다. **본문 폭 상한이 이미 860~880으로 잡혀 있어** 데스크톱에서 한 줄이 길어지는 문제가 없다.

> 이전 분석에서 "trops는 1200 단일"이라고 적었던 것은 오류다. 6차 실측에서 정정됐다.

## 5. 적용 순서

각 단계가 앞 단계에 의존한다. 순서대로 하면 중간에 되돌릴 일이 없다.

| # | 작업 | 파일 | 위험 |
|---|---|---|---|
| **V1** | 액센트 토큰 3줄 교체 | CSS 변수 정의부 | 낮음 |
| **V3** | 버튼 3종 분리 + 세로 패딩 | 버튼 컴포넌트 | 낮음 |
| **V2** | H1·H2 clamp 상한 조정 | 타이포 정의부 | 낮음 |
| **V4** | H1 행간 1.18 → 1.30 | 타이포 정의부 | 낮음 |
| **V5** | H3 계층 신설 | 타이포 + 사용처 | 중간 — 쓸 곳이 있어야 의미 있음 |
| **V6** | `--surface` 조정 + 다크 섹션 | 섹션 스타일 | 중간 — G2 신설과 함께 |
| **V7** | 섹션 패딩 데스크톱 값 | 섹션 스타일 | 낮음 |

**V1~V4는 값 교체뿐이라 한 번에 해도 된다.** V5~V7은 구조 변경(G2 신뢰 섹션 신설)과 묶여야 의미가 있다.

실측 결과 trops가 Anaconda보다 낫거나 이미 적정한 항목이다. **diff에 나왔다고 바꾸면 손해다.**

| 항목 | 현행 | 이유 |

| 본문 행간 | **1.76** | Anaconda 1.50보다 한글에 적합 |
| 헤딩 자간 | **−0.035em** | 한글 헤딩에 맞는 조임 |
| 폰트 | Pretendard 단일 | Poppins+Inter 2종 페어링 따라갈 이유 없음. 가변폰트라 웨이트 추가 비용 0 |
