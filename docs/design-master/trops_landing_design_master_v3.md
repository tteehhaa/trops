## 2. 섹션 구조 13개 (확정)

5지점 회신 결과 12 → 13개가 됐다. ★는 신설·이동.

| # | 섹션 | 상태 | 정렬 | 배경 |
|---|---|---|---|---|
| 1 | 헤더 | 버튼 → **텍스트 링크 강등** | — | `--bg` |
| 2 | 히어로 | 문구 교체 | 중앙 | `--bg` |
| 3 | 안심 문구 | **히어로 직하로 승격** | 중앙 | `--surface` |
| 4 | 2층 카드 | ★신설 · 01:02 = **6:4** | 좌측 | `--bg` |
| 5 | HOW 01·02·03 | 문구 교체 · 번호 마커 유지 | 좌측 | `--surface` |
| 6 | CEPA 조회 | ★**독립 섹션 복원** + eyebrow | 중앙 | `--bg` |
| 7 | 신뢰 | ★신설 · **제품 이미지 2컷** | 좌측 | `--surface-dark` |
| 8 | 로드맵 | 문구 교체 · 2줄 | 중앙 | `--bg` |
| 9 | QnA | ★신설 · 3묶음 14문항 | 좌측 | `--surface` |
| 10 | **마감 CTA** | ★신설 | 중앙 | `--bg` |
| 11 | 사전 등록 폼 | 문서유형 체크 + 처리방침 동의 | 중앙 | `--surface` |
| 12 | 기관 안내 | ★**폼 뒤로 이동** | 좌측 | `--bg` |
| 13 | 푸터 | 통신판매업신고번호 추가 | 좌측 | `--surface-dark` |

### 2-1. 정렬 교차 리듬

Anaconda의 핵심 장치다. **중앙 → 좌 → 중앙 → 좌**를 번갈아 간다.

```
2 히어로     중앙
3 안심문구   중앙   ← 연속. 히어로와 한 덩어리로 읽히게 의도
4 2층카드    좌
5 HOW        좌     ← 연속. 둘 다 순차 구조라 묶임
6 CEPA       중앙
7 신뢰       좌
8 로드맵     중앙
9 QnA        좌
10 마감CTA   중앙
11 폼        중앙
12 기관안내  좌
```

3번이 2번과 같은 중앙인 것은 의도다. **안심 문구가 히어로의 일부처럼 읽혀야** 「입장을 맨 위에서 한 번」이 성립한다.

### 2-2. 우선순위

셋만 고르면 **3 → 4 → 7**.

- **3 안심 문구 승격** — 경쟁사는 같은 말을 페이지 맨 아래 작은 글씨로 쓴다. 우리는 맨 위에서 한다. 이게 차별점이다
- **4 2층 카드** — 이 페이지가 무엇을 파는지 정의하는 자리
- **7 신뢰(제품 이미지)** — 현재 이미지 0장이라 뭘 받는지 안 보인다. 전환에 가장 크게 작용한다

### 2-3. 앵커 연결

| 출발 | 도착 |
|---|---|
| 헤더 「자주 묻는 질문」 | 9 QnA |
| **5 HOW 03단계** | 12 기관 안내 |
| **9 QnA 「어디에 물어볼 수 있나요」** | 12 기관 안내 |

12번이 폼 뒤로 내려가면서 5·9와 멀어졌다. **앵커 두 개로 다리를 놓는다.** 문구는 그대로 두고 링크만 건다.

## 3. 디자인 토큰

### 3-1. 색

```css
/* 액센트 — 클릭 가능한 요소에만 */
--accent:       #1D4ED8;   /* 주 CTA 배경, 텍스트 링크 */
--accent-press: #1E40AF;   /* 호버·눌림 */
--accent-soft:  #EFF6FF;   /* eyebrow 뱃지, 강조 배경 */

/* 잉크 — 4단계 */
--ink:    #0F172A;              /* 헤딩 */
--ink-70: rgba(15,23,42,.70);   /* 강조 본문 */
--ink-64: rgba(15,23,42,.64);   /* 기본 본문 */
--ink-62: rgba(15,23,42,.62);   /* 보조 본문 */
--muted:  #94A3B8;              /* 캡션·비활성 */

/* 배경 — 3층 */
--bg:           #FFFFFF;
--surface:      #F1F5F9;   /* 기존 #F8FAFC에서 변경 */
--surface-dark: #0F172A;   /* 신설 */

/* 선·경고 */
--line:    #E2E8F0;
--warning: #DC2626;        /* 경고 전용. 액센트로 쓰지 않음 */

/* 다크 잉크 — --surface-dark 위에서만 사용, 3단계 */
--d-ink-primary:   rgba(255,255,255,.72);   /* 다크 배경 위 헤딩·강조 본문 */
--d-ink-secondary: rgba(255,255,255,.50);   /* 다크 배경 위 기본 본문 */
--d-ink-tertiary:  rgba(255,255,255,.28);   /* 다크 배경 위 캡션·플레이스홀더 라벨 */
```

**변경분 5개**: `--accent` 3종 교체·신설 / `--surface` 값 하향 / `--surface-dark` 신설 / `--ink-70/64/62` 명시.
**v3 추가**: `--d-ink-*` 3종 정식 등재(2026-08-11) — 클코가 신뢰 섹션(§6) 구현 중 임시값으로 쓰던 흰색 투명도 3단계를 이름 붙여 승격. 값 자체는 변경 없음, 명명만 정식화.

`--surface`를 낮춘 이유: 기존 `#F8FAFC`는 흰색과 명도차가 1.5%뿐이라 섹션 교차가 눈에 안 잡힌다. `#F1F5F9`면 3%가 되어 구분은 되면서 얼룩지지 않는다.

### 3-2. 타입 스케일

| 역할 | 모바일 | 데스크톱 | 굵기 | 행간 | 자간 | 색 |
|---|---|---|---|---|---|---|
| H1 | 36 | **56** | 700 | **1.30** | −0.035em | `--ink` |
| H2 | 28 | **40** | 700 | 1.28 | −0.030em | `--ink` |
| H3 | 22 | **28** | 600 | 1.35 | −0.025em | `--ink` |
| 카드 제목 | 18 | 20 | 600 | 1.35 | −0.02em | `--ink` |
| eyebrow | 12.5 | 12.5 | 700 | 1.5 | +0.14em | `--accent`★ |
| 리드 | 16.5 | 18 | 400 | 1.6 | 0 | `--ink-70` |
| 본문 | 16.5 | 16.5 | 400 | **1.76** | 0 | `--ink-64` |
| 캡션 | 12.5 | 12.5 | 400 | 1.7 | 0 | `--muted` |

★ **정정(2026-08-11, 클코 회신 반영)**: `--accent`는 §3-1의 "클릭 가능한 요소에만" 원칙과 충돌한다. **히어로 eyebrow(클릭 없음, 페이지당 1회)만 `--accent`를 예외로 유지**하고, 카드 소제목·QnA 묶음 제목처럼 반복되는 eyebrow류는 **`--ink-62`**로 내린다. 클릭 요소가 아닌 자리에 액센트를 반복 노출하면 "여기도 눌러야 하나"는 잘못된 신호를 준다.

**폰트는 Pretendard Variable 단일.** 가변폰트라 굵기 추가에 로딩 비용이 0이다.

```css
h1 { font-size: clamp(2.25rem, 4.5vw, 3.5rem); }  /* 36 → 56 */
h2 { font-size: clamp(1.75rem, 3vw, 2.5rem); }    /* 28 → 40 */
h3 { font-size: clamp(1.375rem, 2vw, 1.75rem); }  /* 22 → 28 */
```

### 3-3. 간격·폭

| 항목 | 모바일 | 데스크톱 |
|---|---|---|
| 섹션 상하 패딩 | 60px | **96px** |
| 섹션 좌우 패딩 | 24px | **48px** |
| 컨테이너 최대 폭 | — | 1200px |
| 본문 텍스트 폭 | — | 860px |
| 좁은 콘텐츠(안심 문구·마감 CTA) | — | 680px |

폭 3단(1200 / 860 / 680)은 현행 구조를 유지한 것이다. **본문 상한이 이미 잡혀 있어** 데스크톱에서 한 줄이 길어지는 문제가 없다.

### 3-4. 모서리·모션

```css
--radius:     6px;
--transition: background-color .14s, border-color .14s;
```

둘 다 현행 유지. Anaconda(4px / 0.3s)보다 Pretendard와 어울리고 경쾌하다.

**모션은 이게 전부다.** 패럴랙스·자동 캐러셀·배경 애니메이션 없음. `prefers-reduced-motion` 대응 필수.

## 4. 컴포넌트

### C-1. 버튼 3종

| | 배경 | 글자 | 테두리 | 쓰는 곳 |
|---|---|---|---|---|
| **주** | `--accent` | `#FFF` | 없음 | 히어로 · 마감 CTA · 01 카드 |
| **보조** | `transparent` | `--ink` | `1px --line` | 주 CTA 옆 |
| **텍스트** | 없음 | `--accent` | 없음 | 카드·섹션 내 이동 |

```css
padding: 12px 22px;   /* 세로 0 → 12px. 터치 타깃 44px 확보 */
font: 600 15.5px/1;
border-radius: 6px;
```

**주 CTA가 3회 나온다**(히어로·01 카드·마감). 크기로 위계를 가른다.

- 히어로·마감 = 풀사이즈, 좌우 여백 넓게
- 01 카드 = **카드 폭에 맞춘 인라인**, 한 단계 작게

Anaconda의 "주 CTA 2회" 원칙은 *같은 무게의 CTA가 몇 번 나오나*이지 *버튼이 몇 개냐*가 아니다. 01 카드 CTA는 섹션 CTA가 아니라 카드 내부 요소라 위계가 아래다.

### C-2. 2층 카드 (신설)

```
[H2] 서명 전에 한 번, 서명 후에 한 번.

┌──────────────────────────┐  ┌────────────────┐
│ 지금 쓸 수 있습니다        │  │ 준비 중         │
│                          │  │                │
│ 서명 전 · NDA 대조        │  │ 서명 후 ·       │
│                          │  │ 거래 절차 추적   │
│ 본문 3행                  │  │ 본문 3행        │
│                          │  │                │
│ · 로그인 없이 바로         │  │ · 계약서만 있으면 │
│ · 선착순 20건 무료         │  │ · 기한 7일·1일 전 │
│                          │  │                │
│ [ 무료로 대조해 보기 → ]   │  │ [ 알림 받기 ]    │
└──────────────────────────┘  └────────────────┘
        비중 6                     비중 4
```

- **6:4 비중**은 폭으로 표현. 높이는 맞추지 않는다(내용 길이가 다름)
- 01은 주 CTA(인라인), 02는 **보조 버튼**
- 02 카드에 **가격을 쓰지 않는다**
- 「준비 중」 라벨은 회색조. **경고색 금지**
- 모바일에서 1열로 접히되 **01이 위**

### C-3. QnA 아코디언 (신설)

3묶음 14문항(v3.1 정정 — 원문은 15문항이었고 서명 관련 질문 1개 삭제). 기본 전부 접힘.

- 질문 = 카드 제목 크기(20/600), 답 = 본문(16.5/400, `--ink-64`)
- 묶음 제목 = eyebrow 스타일
- 펼침 표시는 **회전하는 셰브론**. 아이콘에 액센트 쓰지 않음
- 한 번에 여러 개 펼침 허용(하나만 열리는 방식은 비교가 안 됨)
- 「어디에 물어볼 수 있나요」 항목 답 안에 12번 앵커 링크

## 6. 🔴 색이 판정하면 안 된다

**이 제품의 핵심 원칙은 「판단하지 않는다」이다.** 문구에서 금지어를 지켜도 색이 판정을 해버리면 같은 문제가 생긴다.

| 🚫 금지 | 이유 |
|---|---|
| 초록 · 빨강 | 합격 / 불합격 신호 |
| 노랑 · 주황 | 경고 코드 |
| 보라 | AI 신호 |

**대조 결과에서 「다른 부분」을 표시할 때 초록·빨강을 쓰지 않는다.** 다르다는 사실만 표시하고 어느 쪽이 나은지는 말하지 않는다. 밑줄·굵기·배경 톤·좌우 배치 같은 무채색 수단으로 처리한다.

`--warning`은 팔레트에 있지만 **경고 전용**이고 이 랜딩에서는 쓰지 않는다.

## 7. 🔴 준거법·관할 — 화면 설계 제약

대조 기준인 **영국 IPO 공개 서식(OGL v3.0)은 영국법·영국 관할을 전제**로 작성돼 있다. 따라서 사용자 NDA의 준거법이 다른 것은 **차이가 아니라 기준 서식의 전제**다.

**「같음 / 다름」 2상태로는 못 담는다.** 「다름」으로 찍으면 사용자는 "우리 NDA 준거법이 잘못됐나"로 읽는다. 근거 없는 판정이 된다.

**제외도 답이 아니다.** 준거법·관할은 첫 수출 기업이 가장 모르는 조항이다. 안 보여주면 "우리가 안 본 것"이 되어 「공적 절차는 빠짐없이 모으고」와 충돌한다.

**설계안** — 대조 항목 목록과 구조적으로 분리된 별도 블록:

```
── 대조한 항목 ────────────────
  (기존 항목들)

── 대조하지 않은 항목 ──────────
  준거법   귀사 문서에 적힌 값: [원문 그대로]
  관할     귀사 문서에 적힌 값: [원문 그대로]

  기준 서식은 영국법을 전제로 작성돼 있어
  이 두 항목은 대조 대상이 아닙니다.
```

값은 보여주되 대조는 안 한다. 판정도 누락도 아니다. 색은 못 쓰니 **구조와 위치로만** 가른다.

### ⚠️ 미결 — 제품 PRD 확인 필요

제품에 이미 **4종 상태 체계**가 있다(R1 판정어 금지, 4상태만). 「대조하지 않음」이 5번째 상태가 되면 그 원칙을 깬다. **기존 4종 중 어디에 매핑되는지** 확인이 선행돼야 한다. 랜딩이 아니라 제품 사안.

### ⚠️ 일정 의존성

**8/20 캡처가 바로 이 화면을 찍는다.** 지금 상태로 찍으면 준거법이 「차이」로 표시된 이미지가 신뢰 섹션에 나간다. 방금 "차이가 아니다"라고 정해놓고 페이지에서 가장 크게 보여주는 이미지가 정반대를 말하게 된다.

**캡처보다 화면 결정이 먼저다.**

## 10. 레퍼런스

**구조·타이포·배치는 anaconda.com 홈. 색은 참고하지 않는다.**

가져오는 것: 헤딩만 스케일 · 배경 교차 + 다크 섹션 1곳 · 콘텐츠 폭 이중 구조 · 부정형 헤드라인 · 정렬 교차
