### 3-3. 🔴 첫 구현에서 발견해 고친 것 — 카드 **안**의 중복

스크린샷 실측에서, 세 카드 모두 카드 머리의 요약(`.feat-sum`)이 패널 설명
(`.feat-desc`)의 첫 문장으로 **그대로 반복**되는 것이 보였습니다. 두 섹션의 중복을
없애면서 한 카드 안에 같은 중복을 남기면 아무것도 고치지 않은 것이라, 층을 다시
갈랐습니다 — **머리 = 무엇을 하는가 / 패널 = 어디까지·무엇을 더**.

| 카드 | 걷어낸 반복 문장 | 패널에 남은 것 |
|---|---|---|
| 수출 사전점검 | 「받으신 서류를 공개된 표준 서식과 항목별로 맞춰보고, 다른 부분의 위치를 표시해 드립니다.」 | 「다른 부분은 문서 안 어디에 있는지 위치까지 표시해 드립니다. 확인하신 시점도 함께 기록해 둡니다.」 |
| 바이어 확인 | 「거래 상대가 실제로 있는 회사인지, 공개된 정보를 기준으로 맞춰봅니다.」 | 「공개된 정보 안에서만 확인하고, 알선이나 소개는 하지 않습니다.」 |

## 7. 이번에 걸린 함정 3개 (다음 사람용)

1. **`#` 로 시작하는 HTML 주석은 배포본에 남습니다.** `html-minifier-terser` 의 기본
   `ignoreCustomComments`(`/^\s*#/`)에 걸립니다. 「`#feats` 앵커는…」으로 시작한 주석
   하나가 빌드를 멈춰 세웠습니다.
2. **CSS 주석에 `id="..."` 를 큰따옴표째 인용하면 테스트가 오탐합니다.**
   `test/landing-flow-s9.test.js` 가 그 문자열의 **첫 등장**부터 잘라 검사하는데,
   `M`(주석 제거본)은 HTML 주석만 걷고 `<style>` 안 주석은 남깁니다.
3. **트리거 개수를 `M` 으로 세면 안 됩니다.** 같은 이유로 CSS·JS 주석에 인용된
   `[data-timeline-open]` 이 섞여 들어와, 트리거를 지워도 검사가 통과합니다.
   `B`(본문만)로 세도록 고쳤습니다.
