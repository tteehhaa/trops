## 발견·수정한 실제 버그 1건

### `.steps` / `.step` 클래스 충돌 (내가 만든 것 → 즉시 수정)

진행상태 트래커를 처음 `.steps`/`.step` 으로 썼는데, precheck.html 위쪽 「이용 방법」 3단계 섹션이 **그 두 이름을 이미 쓰고 있었다**(`.step { display: grid; grid-template-columns: … }`). 나중에 선언된 `display: flex` 가 그 그리드를 덮어써, 접수확인 화면이 아니라 **관계없는 섹션의 레이아웃**이 깨지는 상태였다.

- 발견 경로: `test/progress-stage.test.js` 의 색상 검사가 red 를 냈고, 원인을 보니 색이 아니라 선택자 범위였다
- 수정: `.progress` / `.progress-step` / `.progress-dot` / `.progress-mark` / `.progress-label` 로 전면 개칭
- 재발 방지: 「addProgress 가 붙이는 클래스는 `progress`/`progress-*` 뿐」 + 「이용 방법 `.step` 의 grid 가 살아 있는가」 두 단정을 테스트에 박음

## 발견한 기존 문서 오류 1건 (정정)

`index.html` FAQ 섹션 주석이 3주 동안 **「3묶음 14문항」으로 잘못 적혀 있었다.** 실제 `.qitem` 은 13개(3+5+5)였다. 채널분기 문항을 더해 지금 실제로 14문항이 됐고, 주석에 실측 정정 경위를 남겼다. 문항 수는 이제 테스트가 단정한다.

### 🔴 라이브 실측으로 드러난 구조적 사실 — 9번은 지금 발화할 수 없다

프로덕션 `intake` 12행이 **전부 `free/none`** 이고 `awaiting_payment` 는 0건이다. 이유는 결함이 아니라 설계다:

```
유상 과금 게이트: isPrecheckPaidChargeEnabled() === false
막고 있는 것    : ['paid_charge_enabled', 'S62-44', 'S62-03']
```

`api/intake.js` 가 유상 경로를 **접수 시점에 거절**하므로(`rejectIfChargeBlocked`) `intake_path='paid'` 행이 아예 생기지 않는다. `status='awaiting_payment'` 는 유상 경로에서만 나오는 상태이므로, **과금 게이트가 열리기 전까지 리마인드 후보는 구조적으로 0건**이다.

- 이것은 9번의 결함이 아니다. 배치는 매일 정상적으로 돌아 0건을 보고한다(오늘 실측이 그것을 보였다).
- **게이트가 열리는 날 자동으로 살아난다** — 추가 작업이 필요 없다. 다만 그날 첫 실행 전에 `npm run remind:preview` 를 한 번 돌려 대상 건수를 확인할 것.
- 반면 **8번(대기공백 기한관리 링크)은 지금 발화한다** — `sendIntakeMails` 안에 있고 무상 경로가 그 함수를 부른다. 다음 무상 접수의 확인메일에 들어간다.

### 남은 −2점의 정확한 내용

Resend 가 실제로 렌더·발송한 메일 본문을 **눈으로 확인한 적이 없다.** 8번은 다음 무상 접수 1건으로, 9번은 과금 게이트 개방 후에 각각 확인 가능하다. 그 전까지는 문면 단정(테스트 12건)이 유일한 근거다.
