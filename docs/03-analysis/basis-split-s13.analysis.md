## 3. 분리와 문맥

### 3-1. 무엇이 어디로 갔나

| 블록 | 전 | 후 |
|---|---|---|
| 무보 인용문 + 출처 | `.trust` 안 상단 | **`.trust` 전체**(한 문장짜리 섹션) |
| h2 「무엇을 근거로 비교하는지 밝힙니다」 | `.trust > .trust-detail` | **`.basis` 제목** (`#basis-title`) |
| 영국 OGL 출처 · 판단배제 · 근거 5종 | `.trust-list`(다크) | **`.basis-list`**(밝은 배경) |
| 대조 결과 캡처 | `.trust` | **탭1 사전점검**으로 |
| `.trust-detail` 헤어라인 | 두 블록을 가르던 구획선 | **삭제** — 섹션 자체가 갈렸습니다 |

`.trust` 는 `<p>` 두 개만 남았고(`O2-b` 가 셉니다), 제목이 없으므로 이름은
`aria-label="지금 확인해야 하는 이유"` 가 집니다.

### 3-2. h2 를 다듬지 않은 이유 (지시가 맡긴 판단)

다듬을 필요가 **없어졌습니다.** 새 자리에서 앞 문장과 낱말로 이어집니다:

> 탭1 요약 「… 공개된 서식과 하나씩 **비교**해서 다른 부분을 표시해 드립니다.」
> ↓ (바로 다음 섹션)
> h2 「무엇을 근거로 **비교**하는지 밝힙니다.」

종전 순서에서는 이 h2 가 상품소개보다 **앞**이라 「비교」가 가리킬 대상이 화면에 없었습니다.
문구를 고칠 문제가 아니라 **자리** 문제였고, 재배치가 그것을 고쳤습니다.
확정본 §6 원문이라 임의 변경 대상이 아니기도 합니다.

### 3-3. 감점 −1 — 좌측 열 하단 여백

1440px 두 열 배치에서 좌측(근거 3줄)이 우측(캡처)보다 짧아 하단에 빈 공간이 남습니다.
`align-items: start` 의 결과이고 **읽기에는 지장이 없어** 이번 범위에서는 손대지 않았습니다.
채우려면 문장을 새로 지어야 하는데, 그것은 「⛔ 리드 문장을 새로 붙이지 마십시오」와
정면으로 충돌합니다. 캡처를 키우는 쪽은 E10-a(560px 상한)에 걸립니다.

### 5-4. 바이어확인 캡처의 실명 처리

지시가 준 URL 의 거래는 **실재 기업**(프랑스 소재)이었고, 화면에는 「제재·수출통제 추가
확인 필요」가 함께 찍힙니다. 그대로 랜딩에 걸면 실명 기업에 그 표시가 붙은 그림이 됩니다.

이 저장소의 캡처 규칙(가상 문서 · 개인정보 0건)을 그대로 적용해, 캡처 직전 DOM 텍스트를
치환했습니다 — 상호 → `ALPHA TRADING CO.` · 등록번호 → `FR12345678901` · 도메인 →
`alpha-trading.example` · 주소창 거래 id → 가상 UUID. 치환 후 원본 식별자 잔존 **0건**을
확인했습니다. 랜딩 캡션이 「가상의 거래로 만든 예시 화면입니다」로 다시 밝힙니다.
