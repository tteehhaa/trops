## 2. 지시별 전후

### 지시 1 — 아코디언 → 탭

| | 전(s11 아코디언) | 후(s12 탭) |
|---|---|---|
| 전환 시 스크롤 | 260ms 뒤 보정(`revealFeat`) | **0px · 보정 코드 없음** |
| 카드/탭 위치 | 재배치로 이동(접으면 `top=-238`) | **불변** |
| 패널 가시율 | 100 / 72.5 / 77% | **셋 다 한 화면** |
| 동시 다중 펼침 | 허용(세로로 쌓임) | 정의상 하나 — **정책 폐기 기록함** |

「스크롤 이슈 원천 차단」이라는 지시를 **보정으로 대응하지 않고 구조로 없앴습니다.**

### 지시 2 — 캡처 축소·프레임·캡션 밀착

| | 전 | 후 |
|---|---|---|
| 표시 폭 | 전폭(최대 1104px) | **560px** |
| 프레임 | 1px 테두리만 | 매트 여백 10px + 테두리 + 그림자 |
| 캡션 | 이미지 밖 `<p>`(간격 16px, 큰 이미지에 묻힘) | **`<figcaption>` 액자 안 · 간격 0px** |

⛔ 브라우저 목업은 덧씌우지 않았습니다 — `c03-result*.jpg` 는 크롬이 이미 이미지 안에
찍혀 있어 두 겹이 됩니다.

### 왼쪽 굵은 선 — 제거(지시가 맡긴 판단)

탭이 선택 상태를 스스로 표시하므로 굵은 선을 얹으면 s11 에서 걷어낸 혼동이 되살아납니다.
그 선이 지던 뜻(생애주기 전 2 · 후 1)은 **탭마다의 eyebrow** 와 **탭 2↔3 거터**(16 vs 54px)가
받았고, 접힌 상태에서만 보이던 것이 **항상 보이게** 됐습니다.

## 3. Check 단계가 잡아낸 실제 결함 1건

**메일 앵커가 sticky nav 뒤에 깔렸습니다** — 실측 도착 위치 `top=0`.

원인: `scroll-margin-top` 을 `.tabs`(줄)에 걸었는데, 이 속성은 **스크롤 목표가 된 요소
자신**에만 듣습니다. 앵커 목표는 `.tab`(버튼)입니다. 버튼으로 옮겨 `top=84` 확인.

이 결함은 **화면이 깨지지 않아서** 눈으로는 안 보입니다 — 이미 발송된 결제확인 메일로
들어온 사람만 겪습니다. 실측 기준을 안 뒀으면 그대로 나갔을 항목입니다.

> 함께: 브라우저는 앵커까지 데려다줄 뿐 열려 있는 것은 첫 탭이므로, 해시로 해당 탭을
> 여는 코드를 넣었습니다. 「링크는 살아 있는데 엉뚱한 탭이 열린다」도 조용한 실패입니다.
