## 1. 포지셔닝 eyebrow + H1 — 진입 히어로는 공유한다

주요 진입 페이지(랜딩 kr·en, precheck)의 히어로는 같은 포지셔닝 문구를 쓴다:

```
[eyebrow]  수출을 앞두고            / BEFORE YOU EXPORT
[H1]       첫 수출이라 무엇부터 봐야 할지 모르겠다면. / First export? Start with the NDA you were sent.
```

- **lead 문단은 예외** — 페이지마다 실제로 하는 일이 다르면(예: precheck는 "자사 서식 우선 대조" 사실) lead는 그 페이지 고유 사실을 설명해도 된다. 통일 대상은 eyebrow·H1(포지셔닝)이지 기능 설명이 아니다.
- 새 진입 페이지를 만들 때 이 eyebrow·H1을 그대로 복사하고, lead만 새로 쓴다.
- **알려진 미반영 구역**: nda.html은 옛 히어로("바이어 서류 사전 확인" eyebrow · "바이어가 보낸 NDA…" H1) 그대로다. 이번 배치 범위 밖이며, 다음 배치에서 §6과 같은 방식으로 맞춘다.

## 2. "상담" 프레이밍 금지 — "점검/준비" 프레이밍만 쓴다

CTA·헤드라인에 "상담"이라는 단어를 쓰지 않는다. 국문 맥락(기관 상담)과 무관하게, 방문자는 "상담"을 "이 서비스에 유상으로 자문을 받는다"로 오해한다 — 이 서비스는 셀프 서비스형 "수출 전 자가 점검" 상품이다.

- 금지: 「상담 전에」, 「상담받기 전」 계열
- 허용: 「수출 전에」, 「점검하세요」, 「확인하세요」 계열 — 히어로 eyebrow("수출을 앞두고")와 같은 프레이밍

## 3. CTA 동사는 능동형 — "알려드립니다"보다 "시작하세요"

아직 열리지 않은 기능(거래 절차 트래킹 등)을 안내하는 CTA라도, 문장은 사용자가 지금 행동하도록 능동형으로 쓴다.

- 지양: 「~열리면 알려드립니다」(회사가 주는 것을 수동적으로 기다림)
- 지향: 「~시작하면, 먼저 시작하세요」(사용자가 지금 신청해서 우선순위를 만드는 행동)
- 예외 없음 — 폼 자체가 대기자 명단(waitlist)이어도 헤드라인은 능동형을 쓴다. "수출 시작하면"이라는 조건절이 아직 기능이 없다는 사실을 이미 담고 있다.

## 4. 헤더 nav 앵커 — 3종 고정, 부가 링크는 별도

확정본 §1 기준, 모든 언어판의 nav-links는 정확히 3개:

```
서비스(#service) · 이용 방법(#how) · 자주 묻는 질문(#qna)
Service(#service) · How it works(#how) · FAQ(#qna)
```

- 로드맵("준비 중인 것"/#next), 문의("문의"/#interest) 같은 하위 섹션은 nav-links에 넣지 않는다 — 진입점이 늘어날수록 "이게 핵심 3가지 중 하나인가?"라는 혼란이 생긴다. 페이지 안에서 스크롤로 도달하게 둔다.
- 앱 링크·언어 전환 같은 유틸리티는 nav-right에 3앵커와 분리해서 둔다(이미 그렇게 되어 있음, 변경 없음).
- 새 언어판·새 페이지를 만들 때 이 3앵커부터 복사한다 — en.html이 먼저 맞았고 index.html이 뒤따라간 것도 이 원칙 때문이다.

## 5. HS코드·협정세율 노출 — 결과 확인 단계 전에는 절대 노출하지 않는다

- nav·hero 등 "결과를 아직 확인하지 않은" 모든 지점에 협정세율 조회 링크·값을 두지 않는다.
- 접수(입력) 단계에서는 "입력하시면 협정 세율도 함께 확인해 드립니다"처럼 **미래 제공을 예고하는 안내문**까지만 허용한다 — 실제 조회 UI·값은 안 된다.
- 실제 조회는 접수 확인(결과) 화면(precheck.html #tariff)과, 독립 상품인 /uae 페이지 자체에서만 노출한다.
- 랜딩 카드 01의 CEPA 데모 블록(en.html·index.html)은 예외로 유지한다 — 확정본 §4에 등재된 잠금 구역이라 코드 판단으로 건드리지 않는다(R-5 결정). 이 예외는 랜딩 카드 한정이며 precheck 상단에는 적용하지 않는다.

## 6. 병렬 카드 레이아웃 — 높이는 stretch + margin-top:auto로 흡수한다

"AVAILABLE NOW / COMING SOON"처럼 콘텐츠 길이가 다른 카드를 나란히 둘 때:

```css
.cards { display: grid; grid-template-columns: 6fr 4fr; align-items: stretch; }
.card > div:last-child { margin-top: auto; }
```

- `align-items: stretch`로 두 카드를 같은 행 높이에 맞추고, 카드 마지막 자식(CTA 버튼을 담은 div)에 `margin-top: auto`를 줘 버튼을 항상 카드 하단에 고정한다.
- 콘텐츠가 늘어나서(CEPA 데모 같은 보조 블록) 카드 높이가 벌어지는 것은 자연스러운 결과지만, 시각적으로는 흡수해서 두 카드가 나란히 끝나 보이게 한다.
- index.html·en.html은 `<style>` 블록을 글자 그대로 복제해서 쓰는 구조라, 이 카드 CSS를 고칠 때는 **두 파일에 동시에** 반영한다(한쪽만 고치면 이번 조사에서 발견한 것과 같은 종류의 드리프트가 재발한다).
