## Executive Summary

| Perspective | Content |
|-------------|---------|
| **Problem** | 트랙A(랜딩 심리설계)는 닫혔지만, **선결제 구조의 가장 취약한 구간 — "돈은 냈고 결과는 아직"** 이 비어 있다. ① 접수 폼이 NDA 하드코딩이라 서류종류 확장 시 새 페이지가 필요하다 ② 환불정책은 있는데 "언제 받는지"(SLA)가 없어 선결제 불안이 남는다 ③ 접수 후 아무 상태 표시가 없어 대기 중 문의·환불로 샌다 ④ 파일까지 올리고 결제만 안 한 고성의도 이탈자를 회수하는 장치가 0건이다. |
| **Solution** | 접수 화면에 문서유형 파라미터 구조(`docType`)를 세우고 NDA 하나만 활성화한다. 결제 영역에 SLA 문구를 환불 문구와 나란히 둔다. 접수확인 화면에 3단계 진행 라벨을 넣되 **단계 근거를 trops_a `precheck_nda_run` 행 존재 여부**에서 읽어 "실제로 일어난 일보다 앞서 말하지 않는다"는 기존 원칙을 깨지 않는다. 결제확인 메일에 기한관리 링크를 붙여 대기 공백을 제품 노출로 바꾸고, 결제 미완료 리마인드 배치를 기존 cron 라우트에 3번째 잡으로 병합한다(Hobby 상한 2개). |
| **Function/UX Effect** | 서류종류 추가가 새 페이지 없이 옵션 1줄로 가능해진다. 선결제 마찰의 두 축(환불 + 시점)이 같은 자리에서 함께 답된다. 검수 대기 구간이 "침묵"에서 "3단계 중 2단계"로 바뀐다. 결제 미완료 건이 하루 1회 회수 시도를 받는다. |
| **Core Value** | 흐름 md §5-1 이 "검토 과정에서 추가된 보완 기능"으로 꼽은 항목 중 **저비용·고효과 5건(1·3·6·10 + §5 확장구조)** 을 한 배치로 닫는다. 큰 기능이 아니라 이탈 지점의 구멍을 메우는 작업. |

### 2.3 결정사항 (사용자 위임 — md 원칙 기준)

| # | 갈림길 | 결정 | 근거 |
|---|---|---|---|
| D1 | KOTRA 문구를 히어로·마감 둘 다인가 한 곳인가 | **마감CTA 한 곳** | 히어로는 주버튼(`비교해 보기`)이 주역이고 `.hero-note`("로그인 없이 바로")가 이미 그 버튼의 마이크로카피다. 마감CTA는 h2 자체가 문의 전용("편하게 물어보세요")이라 신뢰신호가 그 버튼을 직접 지원한다 |
| D2 | `#interest` 의 KOTRA 문구를 남길까 | **제거(이동)** | 중복 노출은 md §4 "이 자리로 재배치"의 뜻과 어긋난다. `#interest` 는 기한관리 알림 신청도 받는 자리라 KOTRA 문구가 거기 있으면 **알림 신청의 신뢰신호로 읽힌다** — 원래 잘못 붙어 있던 위치가 정확히 그것 |
| D3 | 지도 핀 애니메이션 — 가짜 지도를 그릴까 | **안 그린다.** 지도 없는 추상 핀 시퀀스 | `.feat-map` 주석의 명시적 금지(실제 제품 화면이 아닌 것을 제품 화면처럼 보이게 하지 않는다). 핀 마커만 순차 등장시키고 "캡처 준비 중"을 그대로 밝힌다 |
| D4 | 진행상태 라벨이 "검토중"을 말해도 되나 | **`precheck_nda_run` 행이 있을 때만 "검토중"** | md §5-1 10번이 지정한 3단계 문구를 쓰되, 근거를 `intake.status='in_progress'`(사람이 손도 안 댄 건에도 붙음)가 아니라 **대조 실행 증적**에서 읽는다. 기존 `statusLabel` 주석의 "앞서 말하지 않는다" 원칙과 md 문구를 동시에 만족 |
| D5 | 3번째 cron 을 어디에 둘까 | **`api/cron/refund-blocked.js` 에 3번째 잡으로 병합** | Hobby 상한 2개를 이미 다 씀. 같은 파일이 이미 "합칠 때는 한쪽 실패가 다른 쪽을 멈추지 않게" 양식을 세워 뒀고 `runGuarded()` 가 그대로 재사용된다. 시각도 22:40 UTC = **07:40 KST** 로 리마인드 발송에 적절(cleanup 쪽 06:20 KST 보다 나음) |
| D6 | 리마인드가 "3시간 내"를 어떻게 지키나 | **적격 기준은 3시간, 발송 주기는 하루 1회** | Hobby 는 분·시 고정(하루 1회)을 테스트가 단정한다. 3시간은 **후보 선정 임계값**으로 구현하고 최대 24h 지연을 문서에 명시 |
| D7 | `docType` 을 DB 컬럼으로 둘까 | **둔다 (`doc_type text not null default 'nda'`)** | md §5 가 "새 페이지 없이 옵션만 늘어나도록 파라미터 구조"를 요구. 컬럼 없이 화면만 만들면 확장 시 다시 스키마 작업이 필요하고, 운영자 알림에 무슨 서류인지 안 실린다 |
