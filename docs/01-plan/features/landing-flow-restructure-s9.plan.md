## 1. 왜 하는가

지금 index.html 은 **두 번의 설계가 통합되지 않은 채 나란히 얹혀 있습니다.**
리디자인 이전부터 있던 섹션(2층 카드 · HOW IT WORKS)과, s9 흐름 md 가 새로 요구한
심리설계 콘텐츠(경험담 · 신뢰증명 · 3분류 아코디언)가 각자의 자리를 주장한 결과입니다.

실측한 현재 순서와 배경(2026-08-14 · dist 빌드 · 1280px):

| # | 섹션 | 배경 | 높이 |
|---|---|---|---|
| 1 | 히어로 | `--bg` | 607 |
| 2 | 04 2층카드 `.cards-sec` | `--bg` | 740 |
| 3 | `#how` (경험담 + 안심문구 + HOW IT WORKS) | `--surface` | **1592** |
| 4 | 05 아코디언 `.feats-sec` | `--bg` | 430 |
| 5 | 06 신뢰 `.trust` | `--surface-dark` | 1275 |
| 6 | 07 결 `.act` | `--surface` | 358 |
| 7 | 로드맵 `#next` | `--bg` | 831 |
| 8 | FAQ | `--surface` | 1414 |
| 9 | 마감 CTA | `--bg` | 482 |
| 10 | 사전등록폼 | `--surface` | 1009 |
| 11 | 기관안내 | `--bg` | 473 |
| 12 | 푸터 | `--surface-dark` | 451 |

여기서 나오는 문제 4가지:

### P1. 상품소개가 두 번 나온다
`.cards-sec`(#2)가 「수출 사전점검 / 기한 관리」를 개요로 말하고, `.feats-sec`(#4)가
「수출 사전점검 / 바이어 확인 / 기한 관리」를 상세로 다시 말합니다. 같은 상품을 층위만
달리해 두 번 설명하는 구조입니다. 이 중복이 실재한다는 증거는 코드 자신에 있습니다 —
`.cards-lead`(「각각 무엇을 확인해 드리는지는 아래에서 하나씩 펼쳐…」)는 **두 섹션이
중복이 아님을 문장으로 변명하기 위해** 2026-08-13 에 신설된 줄입니다. 구조가 옳다면
변명이 필요 없습니다.

### P2. 감정선이 뒤집혀 있다
md §1 의 감정선은 **기(히어로) → 승(경험담) → 전(신뢰증명) → 결(행동)** 입니다.
그런데 신뢰증명(#5)이 상품소개(#2·#4)보다 **뒤**에 있습니다. 「확신을 만든 뒤 상품을
보여준다」가 「상품을 보여준 뒤 확신을 만든다」로 뒤집혀 있습니다.

### P3. 감정선 사이가 늘어진다
`#how` 하나가 1592px(페이지 최장 본문 섹션)로, 경험담(승) + 안심문구(방어) +
HOW IT WORKS(방법론) 세 가지를 한 섹션에 담고 있습니다. 승과 전 사이에 방법론 설명이
끼어 감정이 식습니다.

### P4. 배경 교차가 안 보인다
`--bg #FFFFFF` ↔ `--surface #F1F5F9` 의 명도차는 **ΔL\* 3.65** 입니다. 코드 주석
자신이 「#F8FAFC 는 1.5%라 안 잡혀서 3%로 내렸다」고 적었는데, 3% 도 여전히 안 잡힙니다.
게다가 위 표에서 #1-#2 가 둘 다 `--bg` 라 교차가 시작부터 한 번 끊깁니다.

## 2. 목표 순서 (대표 지시 + md §1)

```
헤더                                    --bg
히어로 (기)                              --bg
경험담 좌우비교 + 「모르시는 게 당연합니다」 (승)   --surface      ← 교차1
신뢰증명 다크섹션 · 무보 인용 (전)          --surface-dark ← 다크 1회
상품소개 통합 (2층카드 ⊕ WHAT WE CHECK)     --bg
결 CTA                                  --bg           ← md §1 이 지정한 유일한 연속
안심문구 「결정은 대표님 것」                --surface      ← 교차2
HOW IT WORKS                            --bg
로드맵 WHAT'S NEXT                       --surface      ← 교차3
FAQ                                     --bg
마감 CTA                                 --surface      ← 교차4
사전등록폼                                --bg
기관안내                                  --surface      ← 교차5
푸터                                     --surface-dark
```

`상품소개 → 결` 만 같은 배경으로 이어집니다. md §1 시각층매핑이 「핵심기능 3분류 `--bg`
/ 결 `--bg`」로 명시한 자리이고, 사유도 함께 적혀 있습니다 — 「감정선이 신뢰증명 다음
곧바로 행동으로 이어지도록 무관한 기능섹션을 사이에 두지 않음」. 상품을 본 직후의 행동은
**끊는 것이 아니라 잇는 것**이 맞습니다.

## 4. 판단이 필요했던 것 (대표 질문 없이 결정)

### 4-1. 상품소개를 어떻게 「한 번만」 만드는가

**결정: 아코디언 카드의 머리(head)에 개요를, 패널에 상세를 담아 한 카드가 두 층위를 다 진다.**

`.cards-sec` 의 개요 정보(상태줄 · 생애주기 · 한 줄 요약 · 불릿)를 `.feat-btn` 안으로
옮기고, 상세(설명 · 예시화면 · 실행버튼)는 지금처럼 패널에 둡니다. 접힌 상태 = 옛 2층카드,
펼친 상태 = 옛 아코디언. **같은 상품을 두 섹션이 아니라 한 카드가 말합니다.**

이 형태는 이 저장소에 **이미 선례가 있습니다** — en.html 의 기한관리 카드가
`<div class="card feat" id="feat-timeline">` 로 카드와 아코디언을 한 몸으로 씁니다.
국문만 두 섹션으로 갈라져 있던 것입니다.

이 결정으로 사라지는 것 3가지 (전부 **가리킬 대상이 없어져서** 사라집니다):

| 사라지는 것 | 사유 |
|---|---|
| 01 카드의 `[비교해 보기 →]` 보조버튼 | 사전점검 실행 CTA 는 히어로 + 결 2회로 통일(md §1). 카드 안 실행버튼 금지는 이미 `test/landing-flow-s9.test.js` 가 단정 중 |
| 02 카드의 `[기한관리 미리보기]` 트리거 | 그 카드 **자신이** 아코디언이 되므로, 자기를 펼치는 버튼은 의미가 없습니다 |
| `.cards-lead` 의 `<a href="#feats">` | 넘길 「아래」가 없어집니다. 리드 문장은 남되 링크만 걷습니다 |

`#feats` 앵커는 통합 섹션 안 `.feats` 목록에 그대로 붙여 죽은 링크를 만들지 않습니다.

### 4-2. HOW IT WORKS — 흡수인가 존치인가

**결정: 별도 섹션으로 존치.**

3가지 근거:
1. `#how` 는 **헤더 앵커 3종 중 하나**입니다(「이용 방법」). 흡수하면 nav 가 죽거나,
   상품소개 섹션을 가리키게 되어 「서비스」 앵커와 같은 곳으로 갑니다.
2. 상품소개는 「무엇을 확인해 주는가」, HOW 는 「제출→비교→정리 3단계가 어떻게 도는가」로
   **묻는 질문이 다릅니다.** 이것은 04↔05 의 중복(같은 질문, 다른 층위)과 성격이 다릅니다.
3. 확정본 v3.1 §5 원문 가드가 걸린 섹션입니다. 흡수하면 카피를 줄여야 하고 그 순간 가드에
   걸립니다.

**단, 자리는 결 CTA 뒤로 내립니다.** 감정선(기-승-전-결) 안에 방법론 설명이 끼면 안 되고,
「일단 눌러보시라」 다음에 「이렇게 진행됩니다」가 오는 것이 읽는 순서로 자연스럽습니다.

### 4-3. 안심문구를 어디에 두는가

**결정: 결 CTA 바로 뒤 (목표 순서표 그대로).**

대표가 「상품소개 근처나 FAQ 쪽」 두 후보를 주셨습니다. 결 CTA 직후를 고른 이유:

- CTA 를 보고 **누르지 않은 사람**이 다음으로 읽는 자리입니다. 「결정은 언제나 대표님
  것입니다 / ※ 법률 자문 서비스가 아닙니다」는 그 사람의 망설임에 정확히 답합니다.
  마케팅에서 risk reversal 을 ask 직후에 두는 것과 같은 배치입니다.
- FAQ 쪽으로 내리면 페이지 하단이 되어, 「경쟁사는 이 말을 맨 아래 작은 글씨로 쓰는데
  우리는 본문 크기로 한 번 제대로 말한다」는 정본 §2-2 우선순위 1번의 차별점이 사라집니다.
- 상품소개 **앞**에 두면 상품을 보기 전에 선을 긋게 되고, **안**에 두면 3카드의 리듬이 깨집니다.

### 4-4. 같은 스크린샷이 두 번 나오는 문제

재배치 결과 신뢰증명(`.trust`)과 상품소개가 **이웃**이 됩니다. 그런데 두 섹션이 지금
`img/c03-result.jpg` **같은 파일**을 각각 쓰고 있습니다 — 한 화면 거리에서 같은 그림이
두 번 나옵니다. 「중복 제거」 배치에서 이것을 남기면 배치가 자기모순입니다.

**결정: 두 컷을 역할로 갈라 각각 한 번씩만 쓴다.**

| 컷 | 새 자리 | 그 자리의 질문 |
|---|---|---|
| `c03-result.jpg` (문언 대조 표) | `.trust` | 「무엇을 근거로 비교하는가」 = 대조의 **근거** |
| `c03-result-detail.jpg` (확인해볼 질문) | 사전점검 카드 패널 | 「무엇을 받는가」 = 대조의 **결과물** |

`.trust` 의 `.shot-stack` 겹침 콜라주는 2컷 전제라 단일 `.shot` 으로 되돌립니다.

### 4-5. `--surface` 를 얼마나 진하게

**결정: `#F1F5F9` → `#E6ECF3` (ΔL\* 3.65 → 6.86, 1.9배).**

| 후보 | ΔL\* vs `--bg` | 판정 |
|---|---|---|
| `#F8FAFC` | 1.82 | 옛값. 안 보임(코드 주석이 이미 기각) |
| `#F1F5F9` | 3.65 | 현재값. 여전히 안 보임 |
| **`#E6ECF3`** | **6.86** | **채택** |
| `#E2E8F0` (slate-200) | 8.24 | 시각사양서의 「얼룩」 경고 구간에 근접 |

시각사양서 원문 취지(너무 진하면 얼룩져 보인다)를 존중해 slate-200 **직전**에서 멈춥니다.

**부작용과 대응**: `--line #E2E8F0` 는 ΔL\* 8.24 라 새 `--surface`(93.1) 위에서 Δ1.38 —
거의 사라집니다. `--line-on-surface: #CBD5E1` 를 신설하고, `--surface` 섹션에서
커스텀 프로퍼티를 재정의(`--line: var(--line-on-surface)`)해 하위 전체가 자동으로
따라오게 합니다. 이 값의 대 `--surface` 대비는 Δ8.29 로, `--line` 의 대 `--bg` 대비
Δ8.24 와 **거의 정확히 같습니다** — 두 배경에서 선의 무게가 같아집니다.
