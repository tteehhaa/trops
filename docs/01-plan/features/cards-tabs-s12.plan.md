## 2. 지금 구조가 만든 문제 (s11 실측 재확인)

s11 에서 자동 스크롤로 **증상**은 잡았지만 원인은 남아 있었습니다:

- 펼친 카드가 전폭(`grid-column: 1 / -1`)이 되면서 **레이아웃이 재배치**됩니다. 접으면
  3열 줄로 되돌아가 카드가 위로 올라가고(s11 에서 `top=-238` 로 화면 밖), 그것을 다시
  스크롤로 보정해야 했습니다. **스크롤 보정이 필요하다는 것 자체가 구조의 신호**입니다.
- 패널 높이가 콘텐츠마다 달라 1440×900 에서 가시율이 100% / 72.5% / 77% 로 갈렸습니다.
- 동시 다중 펼침을 허용하면 세 패널이 세로로 쌓여 1열 목록으로 퇴화합니다(의도된 퇴화였으나,
  「세 상품을 비교한다」는 3열의 목적과는 반대 방향).

**탭은 이 셋을 구조로 없앱니다** — 패널 자리가 고정이므로 재배치가 없고, 스크롤 보정도
필요 없습니다(지시 1의 「스크롤 이슈 원천 차단」).

## 3. 판단이 필요한 것

### 3-1. 기한관리 왼쪽선 — **제거**로 판단

- 탭은 **선택 상태를 스스로 표시**합니다. 그 위에 왼쪽 굵은 선을 얹으면 s11 에서 사용자가
  지적한 바로 그 혼동(「선택됨처럼 보인다」)이 **탭 안에서 되살아납니다.**
- 다만 그 선이 지고 있던 뜻(**생애주기 축이 전 2 · 후 1 로 갈린다**)은 지켜야 합니다.
  탭에서는 **항상 보이는 두 가지**가 그 일을 대신합니다:
  ① 탭마다 붙는 `.feat-meta`(거래 시작 전 / 전 / 후) ② 탭 2 와 3 사이의 **빈 거터**
  (3열 카드가 쓰던 `1fr 1fr [거터] 1fr` 트랙 구조를 탭 줄이 그대로 물려받음).
- 즉 **선을 지우되 뜻은 남깁니다.** 오히려 접힌 카드에서만 보이던 것이 항상 보이게 됩니다.

### 3-2. 동시 다중 펼침 정책 폐기

「⚠️ 동시 다중 펼침을 허용합니다」는 아코디언 전제의 규칙입니다. 탭은 정의상 하나입니다 —
지시가 구조를 바꾸므로 이 규칙은 **함께 폐기**되며, 그 사실을 주석·검사에 남깁니다.

### 3-3. 캡처 프레임 — 브라우저 목업을 **덧씌우지 않음**

`c03-result.jpg` · `c03-result-detail.jpg` 는 **이미 브라우저 크롬(신호등 + 주소창)이
이미지 안에 찍혀 있습니다.** 여기에 목업 프레임을 또 두르면 크롬이 두 겹이 됩니다.
그래서 **중립 매트(mat) 프레임**(여백 + 얇은 테두리 + 부드러운 그림자)으로 갑니다 —
「액자에 넣은 참고 이미지」로 읽히게.

캡션은 **프레임 안으로** 넣습니다(`<figure>` + `<figcaption>`). 지금은 이미지 밖 별도
`<p>` 라 큰 이미지 아래에서 눈에 안 띕니다. 같은 액자 안에 들어가면 한 덩어리로 읽힙니다.
