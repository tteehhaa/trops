## D-1. 펼침 UX — 「카드 머리를 nav 바로 아래로」

### 고른 안과 기각한 안

지시서가 세 가지를 제시했습니다. **③ 자동 스크롤**을 고르되, 도착 규칙을 바꿉니다.

| 안 | 판단 | 사유 |
|---|---|---|
| ① 펼친 카드가 확장되며 시선 위로 스크롤 | **채택** | ③ 과 사실상 같은 동작. 아래 도착 규칙이 그것입니다 |
| ② 펼친 내용을 3열 아래 전폭 영역에 표시 | **기각** | 패널을 카드 밖으로 빼면 「접힌 카드 = 옛 2층카드, 펼친 카드 = 옛 아코디언」 구조가 깨집니다. `aria-controls` 로 묶인 머리–패널 관계와 **동시 다중 펼침 정책**이 함께 무너지고(패널이 하나뿐인 영역이면 다중 펼침이 불가능), 세 검사 파일이 못질한 `<div class="feat" id=` 구조도 함께 깨집니다 |
| ③ 클릭 시 해당 영역까지 자동 스크롤 | **채택** | 구조를 건드리지 않고 실제 문제(패널 54%가 화면 밖)를 직접 해소 |

### 도착 규칙

```
목표: 카드 머리의 top === 84px   (sticky nav 64 + 여백 20)
```

84 는 새 값이 아닙니다 — 이 파일이 앵커 도착지에 이미 쓰는 값입니다
(`#how, #next, #interest, #service, #qna, #orgs { scroll-margin-top: 84px }`).
같은 값을 쓰지 않으면 **한 페이지 안에 도착 높이가 두 종류**가 됩니다.

⛔ `block: 'center'` 를 쓰지 않는 이유: 카드가 화면보다 높으면 위아래가 함께 잘려
**머리(상품명)까지 화면 밖으로 나갑니다.** 종전 `[data-timeline-open]` 경로가 그랬습니다.

### 타이밍

`.feat-panel` 은 `grid-template-rows: 0fr → 1fr` 을 `.24s` 로 전환합니다.
전환 중에 재면 **접힌 높이**가 잡히므로 `260ms` 뒤에 잽니다.

### 움직이지 않아야 할 때

```js
opening ? (r.top >= 84 && r.bottom <= vh)    // 펼침: 카드 전체가 보이면 그대로
        : (r.top >= 84 && r.top <= vh - 80)  // 접힘: 카드 머리만 보이면 그대로
```
화면에 다 들어와 있는 카드를 눌렀는데 페이지가 튀면, 스크롤이 응답이 아니라 방해가 됩니다.

### 🔴 접기도 봐야 한다 — Check 단계에서 뒤집힌 결정

처음 설계는 「접을 때는 부르지 않는다 — 닫는 사람은 그 자리를 떠나려는 것이 아니다」였습니다.
**실측이 그 전제를 깼습니다.**

| 1440×1600 | 카드 머리 top |
|---|---|
| 펼친 직후 | 84 |
| 접은 직후 (수정 전) | **−238** ← 화면 위로 사라짐 |
| 접은 직후 (수정 후) | 84 |

원인: 펼친 카드는 전폭(`grid-column: 1 / -1`)이라 **자기 줄**을 차지하고, 접으면 3열 줄로
**돌아가면서 위로 올라갑니다.** 스크롤은 그대로이므로 방금 접은 카드가 화면 밖으로 나갑니다 —
무엇을 접었는지 알 수 없게 됩니다. 「그 자리에 있게 한다」는 원래 의도를 지키려면
**접을 때도 봐야 했습니다.**

다만 기준은 다릅니다. 접기에는 **카드 머리**만 요구합니다(펼침처럼 카드 전체를 요구하면
3열에서 옆 카드가 길 때 불필요하게 따라 움직입니다). 접힌 카드는 짧아서 이 조건이 거의
항상 참이고, 위 재배치처럼 **실제로 사라졌을 때만** 되돌립니다.

### 부드러움과 접근성

`window.scrollTo({ top })` 에 `behavior` 를 **넘기지 않습니다.** 넘기지 않으면 CSS
`html { scroll-behavior: smooth }` 를 따르고, 그 값은 `prefers-reduced-motion` 에서
`auto` 로 꺼집니다(1362행). 직접 넘기면 그 규칙을 건너뛰어 움직임을 원치 않는 사람에게
애니메이션이 갑니다.

`[data-timeline-open]` 의 `btn.focus()` 는 **`{ preventScroll: true }`** 로 바꿉니다.
브라우저 기본 포커스 스크롤은 펼침을 기다리지 않으므로 접힌 높이 기준으로 옮겨 놓고,
그 뒤 `revealFeat` 이 정한 위치를 덮어씁니다. 읽어주는 도구를 위한 포커스 이동 자체는
그대로 필요하므로 `focus()` 를 없애지는 않습니다.

### 경로 통합

카드 클릭과 `[data-timeline-open]` 세 곳이 **같은 `revealFeat`** 을 지납니다.
「어디를 눌러도 같은 곳에 도착한다」가 성립해야 합니다.
`setOpen(…, true)` 이 이미 `revealFeat` 을 부르므로 호출부에서 또 부르지 않습니다.

## D-2. 기한관리 강조 — 「테두리」에서 「막대」로

### 왜 `border-left` 가 실패했나

`border-radius: 6px` + `border-left: 3px` 의 조합은 모서리 호에서 3px 짙은 변을
1px 연한 변으로 **테이퍼링**합니다. 그 갈고리가 「둘러싸임 = 선택됨」을 만듭니다.

### 고친 방식

```css
.feats > .feat:last-child { position: relative; }        /* 테두리는 세 카드가 동일 */
.feats > .feat:last-child::before {
  content: ""; position: absolute;
  left: -1px;                 /* 자기 1px 테두리를 덮습니다. 0 이면 두 겹으로 보입니다 */
  top: 10px; bottom: 10px;    /* 6px 모서리 안쪽 — 이것이 핵심입니다 */
  width: 3px; background: var(--ink-70);
  pointer-events: none;       /* .feat-btn 이 카드를 꽉 채웁니다 */
}
```

**위아래를 띄우는 것이 이 방식의 전부입니다.** 0 으로 붙이면 막대가 다시 테두리의
일부로 읽혀 종전 문제가 그대로 재발합니다 — 그래서 검사가 그 여백을 함께 봅니다.

### 왜 1px 테두리를 남겼나 (지시 문면과 다른 부분)

지시는 「전체 테두리를 제거하고 왼쪽 선만」이었지만, 같은 지시가 **정본으로 지목한
`.story-side.is-case` 는 1px 상자 테두리를 그대로 두고 왼쪽 3px 을 더합니다.** 두 문장이
가리키는 곳이 다르므로 정본 쪽을 따랐습니다. 판단 근거:

- 지시의 **목적**은 「선택됨처럼 보이지 않게」입니다. 갈고리가 사라지면 달성됩니다.
- 상자 테두리를 이 한 장만 없애면 세 카드의 「면」이 갈려, 이 카드만 다른 종류로 읽힙니다
  — 지금 문제(이 카드만 튄다)를 **다른 방향으로 되풀이**하는 것입니다.
- `--bg` 위의 `--bg` 카드라 테두리가 사라지면 경계 자체가 사라집니다.

## D-3. 캡처 3장

| 카드 | 파일 | 출처 | 판단 |
|---|---|---|---|
| 사전점검 | `c03-result-detail.jpg` | 기존 | **변경 없음.** 이미 결과화면 캡처입니다. `c03-result.jpg` 로 되돌리면 바로 위 03 신뢰와 한 화면 거리에 같은 그림이 두 번 납니다(2026-08-14 에 그 사유로 갈린 것) |
| 바이어확인 | `c03-result.jpg` (신규 배치) | 기존 | 전용 화면(trops_a 화면 C-06 `/c/[token]/buyer`)은 **유효한 접수 토큰이 있어야 열립니다.** 운영 DB 접근이 막혀 캡처 불가 → 지시서가 미리 승인한 대체안 |
| 기한관리 | `timeline-map.jpg` (**신규 자산**) | app.trops.kr 홈 실캡처 | 자리표시자 해소 |

### 기한관리 — 손그림을 걷어내고 제품 화면을 싣습니다

`img/timeline-map.jpg` 는 로컬에서 띄운 trops_a 의 홈(화면 4) 「계약이 향하는 곳」 패널
(`components/l1/world-map-panel.tsx`)을 **로그아웃 상태로** 찍은 것입니다. 1600×801 · 114KB.

이것이 중요한 이유: 종전에는 랜딩이 제품 정책(FR·AE 2개국 · 애니메이션 0 · 점에 수치 0)을
**손으로 흉내 내고** 있었고, 제품이 바뀌면 조용히 갈라질 통로였습니다. 캡처는 그 화면
자체이므로 세 정책이 자동으로 지켜집니다. 캡처 안에 제품이 스스로 싣는 고지
(「이 지도는 예시이며 실제 계약이 아닙니다」)까지 함께 들어옵니다.

걷어낸 것: `.feat-map` · `.feat-map-note` · `.feat-pins` · `.feat-pin` · `.feat-pin::before`
— 마크업과 CSS 양쪽. 쓰지 않는 클래스를 남기면 다음 사람이 「이 자리에 무엇을 적으라는
뜻」으로 읽습니다.

### 바이어확인 — O4-b 가드를 좁힙니다

`c03-result.jpg` 는 03 신뢰가 이미 씁니다. `test/landing-order-s9.test.js` O4-b 가
「같은 스크린샷이 페이지에 두 번 나오지 않는다」로 그것을 금지하고 있었습니다.

그 규칙이 **지키려던 것**은 주석에 적혀 있습니다: 「한 화면 거리에 같은 그림이 두 번
나지 않는다」. 접힌 아코디언 패널 안의 이미지는 클릭해야 보이므로 그 거리에 놓이지
않습니다. 그래서 판정 범위를 **기본 노출 이미지**로 좁히고, 접힌 패널 안의 재등장은
**명시된 허용 목록**(`ALLOWED_REUSE`)에서만 통과시킵니다 — 목록 없이 풀면
「중복이 원래 되는구나」로 읽혀 배치가 조용히 되돌아갑니다.

⚠️ 상품명 중복 금지: alt·캡션에 「바이어 확인」을 다시 적지 않습니다.
`naming-consistency.test.js` 가 **한 카드 안에서 상품명 1회**를 못질합니다
(한 상품 = 한 번의 설명). 이 자리에서 말할 것은 이름이 아니라 **어디서 진행되는가**입니다.
