## D1. 경험담 — 관할조항 명시

**바꾸는 곳** `index.html` `.story-cmp > .story-side.is-case > .story-body` 한 문장.

```
전) 분쟁이 생기면 상대 국가 법원에서 다투기로 적혀 있었습니다. 소송을 하려면 …
후) 관할조항이 있는데, 분쟁이 생기면 상대 국가 법원에서 다투기로 적혀 있었습니다. 소송을 하려면 …
```

읽는 순서가 **이름 → 뜻 → 질문 → 안심**으로 이어집니다:

```
관할조항이 있는데, 분쟁이 생기면 …          ← 이름과 뜻
이 조항, 본 적 있으신가요?                   ← 「이 조항」의 지시 대상이 앞 문장에 있음
관할조항을 처음 들어보신 대표님도 계셨고 …   ← 같은 이름으로 받음
```

⚠️ 평가어 금지(위험·불리·문제·잘못)는 그대로 지킵니다. 「관할조항」은 조항의 **이름**이지
평가가 아닙니다. 문장 나머지는 한 글자도 바꾸지 않습니다.

## D2. 신뢰증명 — 한마디와 근거 디테일을 갈라 놓는다

### D2-1. 순서

```
전)  h2(40)  →  인용문(28)  →  출처  →  근거 3줄(16.5)  →  캡처
후)  인용문(H1 스케일)  →  출처
     ────────── 헤어라인 + 큰 여백 ──────────
     h2(40)  →  근거 3줄(14.5)  →  캡처
```

인용문이 먼저 오는 이유는 두 가지입니다.

1. 지시 그대로 **제일 중요한 한마디**를 맨 앞·가장 크게 두기 위해서입니다.
2. h2「무엇을 근거로 비교하는지 밝힙니다.」가 실제로 소개하는 것은 **그 아래 근거 3줄과
   캡처**입니다. 지금은 그 h2 가 근거가 아니라 인용문 위에 얹혀 있어, 제목과 바로 아래
   내용이 서로 다른 것을 말합니다. h2 를 근거 묶음의 머리로 내리면 그 어긋남도 함께 풀립니다.

⚠️ h2 의 **크기·굵기·색은 손대지 않습니다**(40 / 700 / `--d-ink-primary`). 와이어프레임 C
블록이 못박은 값이고, 토큰 주석(`--d-ink-*`)이 그 값을 근거로 색 체계를 정해 뒀습니다.
자리만 옮깁니다. `aria-labelledby="trust-title"` 도 그대로입니다.

### D2-2. 타이포 (신규 값 0 — 전부 기존 스케일 재사용)

| 요소 | 전 | 후 | 근거 |
|---|---|---|---|
| `.stat-line` | `.h3` 28 / 600 / −0.025em | **H1 스케일** `clamp(2.25rem, 4.5vw, 3.5rem)` / 1.30 / −0.035em / 700 | `.hero h1` 과 같은 값. 시각사양 3-4 「H1·H2만 스케일」 |
| `.stat-line` 폭 | 30ch | 20ch | `.hero h1`(21ch)에 준하는 덩어리. 1440px 에서 3줄 |
| `.stat-src` | 12.5 / `--d-ink-tertiary` | 그대로 | 출처는 눈에 띄면 안 됩니다 |
| `.trust-list p` | 16.5 / 1.76 | **14.5 / 1.75** | `.rm-diff` 와 같은 값(기존 값 재사용) |

`class="h3"` 는 `.stat-line` 에서 **뗍니다.** 크기를 전부 덮어쓸 거라면 남겨 둘 이유가 없고,
남기면 다음 사람이 「H3 계층」으로 읽습니다.
→ `test/landing-order-s9.test.js:318` · `test/landing-flow-s9.test.js:90` 의
`class="h3 stat-line reveal"` 단정을 **클래스 순서·개수에 무관한 형태로** 함께 고칩니다.
두 검사의 뜻(「인용문에 `.reveal` 이 붙어 있는가」)은 그대로 유지합니다.

### D2-3. 구획

```css
.trust-detail {
  margin-top: clamp(48px, 6vw, 72px);
  padding-top: clamp(32px, 4vw, 44px);
  border-top: 1px solid var(--d-line);
}
```

`--d-line`(흰색 헤어라인 .28)은 다크 섹션의 기존 선 토큰입니다 — 신규 토큰 없음.

⚠️ 근거 3줄을 `<details>` 로 접지 않습니다(Plan §3). 「비교 항목은 저희가 만들지 않습니다」는
이 페이지의 차별점이라 기본 화면에서 사라지면 안 됩니다.

## D3. 정렬 규칙 — 이름을 주고 못질한다

### D3-1. `.sec-center` 로 모은다

세 곳에 복사돼 있던 같은 4줄을 클래스 하나로 모읍니다.

```css
/* 중앙정렬은 「선언·행동」 세 섹션뿐입니다 — 결 CTA · 안심문구 · 마감 CTA.
   설명·근거·목록은 전부 좌측입니다. */
.sec-center { display: flex; flex-direction: column; align-items: center; text-align: center; }
```

`.act-inner` · `.assure-inner` · `.close-cta-inner` 는 `padding-block` 과 `gap` 만 갖습니다.
마크업 세 곳에 `sec-center` 를 붙입니다.

### D3-2. 결 CTA 는 여백으로 자기 자리를 갖는다

```css
.act-inner { padding-block: clamp(88px, 11vw, 136px) clamp(60px, 8vw, 96px); }
```

위쪽만 기준값(60~96)보다 한 단계 키웁니다. 상품소개와 배경이 같아 경계선이 없는 자리라,
**침묵이 경계 역할**을 합니다. 아래쪽은 기준값 그대로 — 뒤따르는 안심문구와는 배경이
갈리므로 더 벌릴 이유가 없습니다.

⛔ `.act` 에 `border-top` 이나 다른 배경을 주지 마십시오. s9 O7 검사에 걸리고, 「상품 →
행동을 한 덩어리로 읽히게 한다」는 결정이 취소됩니다.

### D3-3. 검사로 못질

`test/landing-emphasis-s10.test.js` 가 확인합니다:
- 중앙정렬을 만드는 규칙은 `.sec-center` 하나뿐이다 (`text-align: center` 를 직접 적은
  섹션 규칙이 없다)
- `sec-center` 를 쓰는 마크업은 정확히 3곳이고, 그 셋은 결·안심문구·마감CTA 다

## D4. 상품소개 — 3열(2+1) · 펼치면 전폭

### D4-1. 브레이크포인트

| 폭 | 배치 |
|---|---|
| ~1023px | 지금 그대로 세로 1열 (`.feats` = flex column) |
| 1024px~ | 3열 그리드 |

1024 인 이유: 1200 컨테이너·좌우 48 여백 기준으로 열 하나가 **290px 이상**이어야 카드
머리(생애주기 + 상태줄 + 22px 제목)가 두 줄 안에 들어갑니다. 769 에서 3열로 가면 열이
215px 라 상태줄이 매번 줄바꿈합니다.

### D4-2. 2 + 1 구획을 그리드 트랙으로 만든다

```css
@media (min-width: 1024px) {
  .feats {
    display: grid;
    grid-template-columns: minmax(0,1fr) minmax(0,1fr) clamp(8px,1.5vw,24px) minmax(0,1fr);
    gap: 16px;
  }
  .feats > .feat:last-child { grid-column: 4; }
  .feat[data-open="1"] { grid-column: 1 / -1; }
}
```

3열째는 **빈 거터 트랙**입니다. CSS 그리드는 거터마다 다른 폭을 줄 수 없으므로 트랙 하나를
비워 씁니다. DOM 에 빈 `<div>` 를 넣지 않는 이유는 읽어주는 도구에 뜻 없는 요소가 잡히기
때문입니다. 결과: 1↔2 사이 16px, 2↔3 사이 40~56px.

`:last-child` 로 기한관리를 고르는 이유: 카드에 새 클래스를 붙이면 세 검사 파일이
`<div class="feat" id="` 를 **정확히** 찾고 있어 함께 깨집니다. 카드 순서(사전점검 ·
바이어확인 · 기한관리)는 `test/landing-order-s9.test.js` O4 가 제목 배열로 못질하고 있으므로
`:last-child` = 기한관리는 검사로 보장됩니다.
⚠️ 카드 순서를 바꾸면 이 선택자가 다른 카드를 가리킵니다. O4 를 먼저 보십시오.

### D4-3. 기한관리의 「다른 강조」

```css
.feats > .feat:last-child { border-left: 3px solid var(--ink-70); }
```

경험담의 `.story-side.is-case` 와 **같은 표시법**입니다(굵은 왼쪽 선 · `--ink-70`).
페이지 안에서 이미 쓰는 언어를 재사용합니다.

⛔ 액센트(`--accent`)·경고색(`--warning`)을 쓰지 마십시오 — 판정색 금지(시각사양 1-3).
⛔ 배경을 `--surface` 로 채우지 마십시오 — 다른 두 카드와 「면」이 달라지면 세 카드가
   같은 종류로 안 읽히고, O6 검사의 취지(섹션 배경 직접 칠하기 금지)와도 얽힙니다.

이 선은 모바일 1열에서도 그대로 남습니다 — 폭이 좁아도 「이건 거래 시작 후」라는 표시는
같아야 합니다.

### D4-4. 카드 높이

```css
@media (min-width: 1024px) {
  .feat { display: flex; flex-direction: column; }
  .feat-btn { flex: 1; }
}
```

그리드 기본 `stretch` 로 세 카드의 높이가 같아지고, 그 높이를 카드 머리가 채웁니다
(안 하면 카드 아래에 빈 띠가 남습니다).

### D4-5. 펼치면 전폭 — 기각됐던 3열을 되살리는 조건

2026-08-14 에 3열이 기각된 사유는 「펼친 패널의 캡처가 1/3 폭이라 안 읽힌다」였습니다.
`grep` 로 실측하면 사전점검 카드의 캡처는 1487×523 이라 350px 폭에서 높이 123px 입니다.

`.feat[data-open="1"] { grid-column: 1 / -1 }` 가 그 사유를 해소합니다 — 펼친 카드는
지금(1열)과 **똑같은 전폭**을 갖습니다.

⚠️ 세 카드가 모두 같은 방식으로 넓어집니다. 카드마다 다르게 하지 마십시오 — 「세 카드는
   반드시 같은 인터랙션」 가드(`test/landing-flow-s9.test.js`)가 여기 걸립니다.
⚠️ 펼침이 여러 개 동시에 허용된다는 정책은 그대로입니다. 셋 다 펼치면 세 줄 전폭이 되어
   기존 1열 목록과 같은 화면이 됩니다 — 의도된 퇴화입니다.
