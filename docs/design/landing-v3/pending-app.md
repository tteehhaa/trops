## 폼에 맞춰 둔 것 (계약 2-1)

| 칸 `name` | 화면 | 값 |
|---|---|---|
| `company_name` | 회사명(필수) | 1~120자 (`maxlength="120"`) |
| `email` | 담당자 이메일(필수) | 이메일 꼴 · 254자 |
| `industry` | 업종(필수) | `machinery` 기계·부품 · `electronics` 전기·전자 · `cosmetics` 화장품·생활용품 · `food` 식품 · `chemicals` 화학·소재 · `other` 기타 |
| `region` | 지역(필수) | `capital` 서울·경기·인천 · `chungcheong` 충청 · `jeolla` 전라 · `gyeongsang` 경상 · `gangwon_jeju` 강원·제주 |
| `consents.collection` | 동의 체크(필수) | 보낼 때 `consents: { collection: true }` 로 묶습니다 |
| `requested_work` | 숨은 칸 · 히어로 입력칸·명령 버튼이 채움 | 500자에서 자릅니다 · 폼 위 「요청하신 업무」 상자에 보입니다 |
| `referral_code` | 숨은 칸 · `?ref=` 에서 채움 | 영문·숫자·하이픈 4~32자만 담고 대문자로 맞춥니다(아니면 비워 둡니다) |
| `website` | 봇 방지 · 화면 밖 칸 | 빈 문자열 그대로 |
| `elapsed_ms` | 봇 방지 · 숨은 칸 | 페이지를 연 시각부터 누를 때까지(밀리초) · 지금도 누를 때 채웁니다 |
| `notice_version` | 숨은 칸 | ⚠️ **자리표시 `pilot-apply-draft`** — 동의 문구가 확정되면 `pilot-apply-YYYY-MM-DD` 로 |

- 동의 문구: 「개인정보 수집·이용에 동의합니다. 회사명·이메일·업종·지역과 요청하신 업무, 받으신 소개 코드를
  초대 안내와 연락, 장부 사전 준비에 이용하며 **신청일부터 1년** 보관합니다.」
  — ⚠️ **보관 기간은 자리표시입니다**(대표 지시). 앱이 확정하면 이 문장 · 방침 행 · `notice_version` 을 함께 고칩니다.
  — 계약 0-1: 「요청하신 업무」는 동의 기록의 범위 코드에 실리지 않으므로 **동의 문구가 글로 적어야** 합니다.
    계약이 적은 목적(시범 참여 선정 · 초대 · 장부 미리 채움 · 가입 뒤 첫 화면에 요청 업무 채움 · 소개 수 집계)과
    지금 문구를 4단계에서 맞추십시오.
- **소개 문구는 「소개해 주시면 먼저 연락드립니다」로 통일했습니다** — 공지 띠 · 신청 섹션 머리 · FAQ 「초대는
  어떤 순서로…」 · 완료 화면. 앱 응답의 `referral.note` 와 같은 문장입니다.
  「순서가 앞당겨집니다」 · 「세 칸씩」 문구는 **전부 지웠습니다** — 앱은 소개로 순번을 자동으로 바꾸지 않습니다(계약 2-6).
- **완료 화면**(`#done`)은 자리만 있고 제출이 막혀 있는 동안 **뜨지 않습니다**:
  - `#qNum` — `○`(자리표시) → 응답 `queue.position` · 문장 「○번째로 신청하셨습니다」
  - `#qBasis` — 비어 있음 → 응답 `queue.basis` 를 **그대로**(순번은 초대 순서의 약속이 아니라는 문장 · 계약 2-5)
  - 「소개해 주시면 먼저 연락드립니다.」
  - `#myRef` — 소개 링크 자리(비어 있음) · 「링크 복사」 · 「카카오톡으로 보내기」(비어 있으면 아무것도 안 함)

## 4단계에서 할 일

### ① 폼 제출 연결
1. `SUBMIT_ENABLED = true` · 본문을 JSON 으로: 필수 다섯 + `requested_work`(있으면) + `referral_code`(있으면) +
   `consents: { collection: true }` + `notice_version` + `website: ""` + `elapsed_ms`. `Content-Type: application/json`.
   - ⚠️ `elapsed_ms` 는 3000 이상이어야 합니다 — 사람이 3초 안에 다 채울 수는 없지만, 붙여 넣기 자동완성으로
     빨리 누르는 경우의 안내 문구를 정하십시오(`bot` 오류).
2. 응답 갈래(계약 2-5 · 오류 표): 201 → 폼을 내리고 `#done` 을 채워 보여 줌 · 400 `invalid` → `fields[]` 를 칸 오류로 ·
   403 `origin` · 409 `not_updatable` · 429 `rate_limited`(`retry_after`) · 503 `closed` / `not_effective` → 문의 메일 안내 ·
   그 밖 → 「보내지 못했습니다」 + 메일 주소. ⛔ 저장이 실패했는데 「접수되었습니다」로 말하지 않습니다.
3. 소개 링크 꼴을 정하십시오 — 계약의 예는 `https://trops.kr/pilot?ref=TR-3NV8QD` 인데 **랜딩에 `/pilot` 이 없습니다.**
   지금 폼은 `/?ref=` 를 읽습니다. 제안: `https://trops.kr/?ref={code}#apply` (페이지를 새로 세우지 않음).
4. 응답의 `quick_check`(먼저 챙길 것 3가지 + 전체 보기 링크)를 완료 화면에 보일지 정하십시오 — 계약은
   「랜딩 화면이 `queue`·`referral`·`quick_check` 를 바로 보여 주는 것이 정본」이라고 적습니다.
5. 선택: `acquisition`(utm · ref · landing_path)을 실을지. 싣는다면 방침 항목에도 적어야 합니다.
6. Preview 에서 시험하려면 앱 Preview 환경변수 `PILOT_APPLY_ALLOWED_ORIGINS` 에 랜딩 Preview 주소를 넣고 앱 Preview 를
   다시 배포해야 합니다(계약 1).
7. `assets/track.js` 의 「다음 걸음」(`nextStepOf`)은 목적지로 셉니다 — 신청은 같은 페이지 안이라 잡히지 않습니다.
   신청 완료를 셀지 정하십시오(라벨 `apply-submit` 클릭은 이미 셉니다).

### ② 방침에 시범 신청 행 추가 (계약 0-1 — **앱을 켜기 «전»에** 먼저)
- `privacy.html` §01: 「받는 개인정보는 문의·견적 요청·출시 알림 신청 **한 자리**」가 거짓이 됩니다 → 두 자리로.
- §02 표에 시범 신청 행: 항목(회사명 · 이메일 · 업종 · 지역 · 요청하신 업무 · 소개 코드 · 동의와 시각 · 선택 칸을 받게 되면
  그 칸들) · 목적(계약 0-1 의 다섯) · 보관(확정값) · 요청 빈도 제한용 IP 해시(이틀) · 파일을 받게 되면 그 항목.
- §03 보관 문단 · §04 처리 위탁/국외이전 표에 그 기록의 보관처(앱 본체 DB · 서울).
- `en-privacy.html` 같은 네 자리 — 「one place only」도 함께.
- 신청 폼 동의 문구와 §02 행이 **같은 말**이어야 합니다(contact.html 동의 블록과 같은 규칙).

### ③ §02 · §03 · §04 메일 문장 재정리
- 계약 2-5: **시범 신청은 접수 메일을 보냅니다**(대기 순번 · 소개 코드 · 1분 진단 요약 · 신청 이메일로).
  2026-09-29 hotfix 에서 문의 접수 쪽을 「접수 때 메일은 발송되지 않습니다」로 고쳤으므로, 두 자리가 서로 다른 말을
  하게 됩니다 — 시범 신청 행에는 그 메일을 적고, 문의 행은 그대로 둡니다.
- 앱에서 문의 접수의 운영자 알림을 되살리면 문의 행 · §03 문단 · `contact.html` 성공 문구를 함께 다시 고칩니다.
- §04 Resend 행(「안내·확인 메일 발송」)을 실제 발송과 맞춥니다. §06 「확인 메일에는 자료를 첨부하지 않고 링크만」도 함께.

### ④ 개정 고지
- §07 에 새 소제목 + 머리 「개정 · 시행」 줄 — **국문·영문 같은 날짜**(`test/ga-policy.test.js` 가 대조합니다).
- 시행일 = 배포일. 받는 항목이 **늘어나는** 개정이므로 불리한 변경인지 판단해 적습니다(§07 첫 문단의 약속).
