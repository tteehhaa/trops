## `/nda` · `/refund` 의 9바이트 — 무엇이고 왜 괜찮은가

이번에 소스에 **설명 주석을 새로 넣은 두 페이지**입니다. 빌드는 주석을 떼지만
그 자리의 들여쓰기 공백은 남깁니다 — `collapseWhitespace` 를 **일부러 꺼 둔** 결과입니다
(켜면 한글 인라인 요소 간격이 바뀝니다 · `scripts/build-static.js` 머리주석).

남은 것은 블록 요소 **사이**의 `\n` + 공백 8개입니다(`</p>` 와 `<p>` 사이 ·
`</h2>` 와 `<p>` 사이). 텍스트 흐름 안이 아니라 렌더링에 영향이 없습니다.

토큰화 전(`HEAD`)과 후를 4단계로 대조했습니다 — 8페이지 전부 동일:

| 대조 축 | 결과 |
|---|---|
| 태그 순서열 | 8/8 동일 |
| 화면에 보이는 문구 | 8/8 동일 |
| `<script>` 블록 전문 | 8/8 동일 |
| 공백 제외 전문 | 8/8 동일 |

즉 **차이는 주석 자리에 남은 공백뿐**이고, 이 저장소가 빌드에서 지키기로 한 두 축
(태그 구조 · 화면 문구)은 그대로입니다.

### ⚠️ 검증 과정에서 낸 실수 2개 — 같은 함정에 다시 빠지지 않도록

1. **`cd` 가 이어져 산출물을 자기 자신과 비교했습니다.**
   `(cd base && build)` 다음 줄의 `build` 도 `base` 에서 돌아서, `diff base/dist dist` 가
   같은 폴더를 비교하고 「완전 동일」이 나왔습니다. **무의미한 통과였습니다.**
   → 서브셸로 감싸거나 절대경로를 쓰십시오. 처음에 이걸 믿고 넘어갔다가
     프로덕션 바이트 비교에서야 9바이트 차이가 드러났습니다.

2. **배포본의 CSS 선택자 순서가 바뀝니다.**
   `h3, .h3` 가 배포본에서 **`.h3,h3`** 로 나옵니다(빌드의 CSS 처리가 선택자 목록을
   정렬합니다 · 뜻은 같습니다). 문자열로 찾으면 「규칙이 없습니다」 오탐이 납니다.
   → `verify-deployment.js` 는 쉼표로 갈라 **집합으로** 대조합니다.

   같은 이유로 **소스는 주석을 뺀 상태로 세야 합니다.** `index.html` 주석에
   「`clamp(60px, 8vw, 96px)` 였는데 …」라는 설명이 있어서 소스 11곳 · 배포본 10곳으로
   세어져 통과할 것이 실패로 나왔습니다.

### cron 라우트가 실재하는지 어떻게 구분했는가

`CRON_SECRET` 미등록이라 라우트는 **모든 호출에 404** 입니다. 그래서 HTTP 상태만으로는
「라우트가 없다」와 「라우트가 거절했다」가 구분되지 않습니다. 헤더로 갈랐습니다 —
우리 핸들러는 인증 검사 **앞에서** `Cache-Control: no-store` 를 세팅하므로 404 에도 남습니다.

| | 상태 | `cache-control` | 본문 | `x-vercel-error` |
|---|---|---|---|---|
| `/api/cron/cleanup-expired` | 404 | **`no-store`** (우리가 세팅) | **0자** | 없음 |
| `/api/cron/does-not-exist-xyz` | 404 | `public, max-age=0, …` | 79자 | `NOT_FOUND` |

→ **함수가 실제로 실행되고 인증 게이트에서 닫혔습니다.**
틀린 secret(`Bearer definitely-wrong-secret`) → 404 · `POST` 무인증 → 404 도 확인.

### 🔴 이 부분은 「완료」가 아닙니다 — 저장소 밖 요인으로 보류

**cleanup-expired cron 의 실제 삭제 집행**은 `CRON_SECRET` 이 Vercel Production 에
등록되기 전까지 일어나지 않습니다. 지금 상태는 「매일 돌되 404 로 끝나고 아무것도
지우지 않는다」입니다. 이것은 설계된 fail-safe 이지만 **30일 보관 약속은 아직
자동으로 지켜지지 않습니다** — 그때까지는 `npm run cleanup:apply` 를 사람이 돌려야 합니다.

`INTAKE_SUPABASE_URL` · `INTAKE_SUPABASE_SECRET_KEY` 는 이미 Production 에 있으므로
**남은 조건은 `CRON_SECRET` 하나뿐**입니다.
