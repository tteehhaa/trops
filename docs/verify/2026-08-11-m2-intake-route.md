### 사유 문면 — 새로 쓴 문장이 하나뿐입니다

| 사유 코드 (trops_a `PreflightStop`) | 이 저장소가 보여 주는 문장 |

  `precheck.html` 의 `#textlayer-msg` 와 글자 단위로 비교합니다. 한쪽만 고치면 red 입니다.

  지시가 언어 이름·「지원하지 않습니다」를 금지했습니다. ⛔ **두 문면을 통일하지 마십시오** —
  화면이 다르고(app / www) 규칙이 다릅니다. 통일하면 테스트가 red 를 냅니다.
- 모르는 사유에 **다른 문장을 두지 않은 것도 결정**입니다. 문면이 갈리면 그 차이 자체가

### 자동 환불에서 재는 것은 「안 움직이는 경우」입니다

돈을 움직이는 배치라, 취소 호출 수를 **응답이 아니라 가짜 토스로 나간 요청 수**로 셉니다.

| 상황 | 취소 호출 |
|---|---|
| 표를 못 읽음 (없음 · 컬럼 다름 · 접속 실패) | **0건** |
| 환불 컬럼(0-F) 미실행 | **0건** — 표를 읽으러 가기도 전에 멈춥니다 |
| `blocked` 행은 있지만 현재 `ok` (되돌려짐) | **0건** |
| 자료를 이미 전달한 건 | **0건** — 사람에게 넘깁니다 |
| `--apply` 없음 | **0건** |
| 이미 환불된 건 (같은 날 두 번 실행) | **0건** |
| `blocked` + 유상 + 결제완료 + 미환불 + 미전달 | **1건** + 안내메일 1통 |

한 번에 훑는 `blocked` 행 수에 상한(500)이 있습니다. 상한에 닿으면 **말합니다**(`truncated`) —
조용히 자르면 「전건 확인했다」로 읽히고, 밀려난 오래된 건은 아무도 모르는 사이 환불되지
않은 채 남습니다.

- 안내메일은 **환불 뒤**에 나갑니다(메일 대역이 「보내는 순간 취소가 끝나 있었는가」를 기록합니다).
- 메일이 실패해도 환불을 되돌리지 않습니다 — 돈은 이미 돌아갔고 메일은 다시 보낼 수 있습니다.

## ⚠️ trops_a 와 확정해야 하는 것 (착수 전 확인 필요)

   확인이 필요합니다. 표만 있고 행이 없으면 우리 쪽은 그대로 무동작입니다 — 장애가

   (PostgREST OpenAPI 로 확인) FK 를 걸지 않은 이유까지 컬럼 주석에 들어가 있습니다.
   「조용히 0건」이 되는 가장 찾기 어려운 실패 방식이었으므로 1순위였습니다.

영향이 없었고(확인 조회 `200` · `routeNotice` `null`), 환불 cron 은 ① 환불 컬럼 선행
검사에서 던져 표를 읽으러 가기도 전에 멈췄습니다 — 취소 호출 **0건**.

그 뒤 같은 날:

1. **0-F 를 실행했습니다**(우리 몫). Supabase SQL Editor.
2. **`precheck_intake_route` 가 생겼습니다 — 만든 쪽은 `trops_a` 입니다**(우리가 만들지
   않았습니다. 0-G 는 참조본이고 실행 금지입니다). PostgREST OpenAPI 로 확인한 모양이
   **0-G 계약과 정확히 일치**합니다 — `intake_id uuid` 이름까지, FK 를 걸지 않은 이유가
   컬럼 주석에 그대로 들어가 있습니다. 1순위로 적어 둔 「컬럼 이름이 어긋나면 조용히
   0건」 위험은 **닫혔습니다.**

그래서 우리 쪽 배선은 프로덕션에서 **끝까지 완주합니다.** `npm run refund:blocked:preview`
(프로덕션 자격증명 · `--apply` 없음):

```
[미리보기] 처리 불가로 기록된 건이 없습니다.
요약 — 확인 0건 · 후보 0건 · 환불 0건 · 이미환불 0건 · 되돌려짐 0건 · 사람몫 0건 · 실패 0건
```

컬럼 검사 통과 → 표 읽기 성공(`available:true`) → 후보 0건 → **취소 호출 0건** · 종료코드 0.
cron 도 이제 `available:false` 를 밟지 않으므로 `502` 가 아니라 `200` 입니다.

### 지금도 「조용히 대기」입니다 — 대기 지점이 한 겹 옮겨갔을 뿐입니다

| 센 것 | 행 수 |
|---|---|
| `precheck_intake_route` 전체 | **0** |
| └ `route='blocked'` | **0** |
| `intake` 전체 | 2 |
| └ 유상·결제완료·미환불 | **0** |

표는 섰지만 **행이 아직 하나도 없습니다** — `trops_a` 의 쓰는 쪽(정본 함수 · cron)이 아직
돌지 않았습니다. 그리고 돈이 걸린 접수 자체가 0건이라, 지금 `blocked` 행이 들어와도
환불될 건이 없습니다. 대기 지점이 「표가 없어서」에서 **「행이 안 들어와서」**로 옮겨갔습니다.

⚠️ **아직 아무도 실제 행으로 확인하지 못했습니다.** 첫 `blocked` 행이 들어오는 순간
확인 화면 문면과 환불 배치가 동시에 처음 실물로 동작합니다. 그때 한 번은 봐야 합니다.

⚠️ `available:false`(표를 못 읽는 경로)는 이제 프로덕션에서 재현되지 않습니다 — 재현하려면
표를 지워야 하므로 재지 않습니다. 그 경로는 `test/route-refund.test.js` 로만 덮여 있습니다.
표가 뒤에 지워지거나 이름이 바뀌면 **매일 `502`** 가 됩니다. 같은 파일이 env 미등록에는
「매일 500 이 나면 경보가 무뎌집니다」를 이유로 `200` 을 주고 있어 **판단이 갈려 있습니다** —
지금은 걸리지 않는 길이지만 갈린 채로 남아 있다는 사실은 적어 둡니다.

### 확인하지 못한 것 — PostgREST 로는 안 보입니다

- **색인 2개**(`(intake_id, decided_at desc)` · `(decided_at desc) where route='blocked'`).
  지금은 0행이라 영향이 없지만, 행이 쌓이면 우리 읽기 둘이 그대로 풀스캔이 됩니다.
- **`route` check 제약**(`in ('ok','blocked')`). 없어도 우리 코드는 `ROUTES` 허용목록으로
  막아 모르는 값을 없는 것으로 둡니다.

둘 다 `trops_a` 에 확인을 요청해야 합니다.

`CRON_SECRET` 은 이미 설정돼 있습니다(cleanup 배치가 쓰고 있습니다). 새로 넣을 env 는 없습니다.
