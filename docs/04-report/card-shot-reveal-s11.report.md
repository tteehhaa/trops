## 2. 지시 1 — 왜 「자동 스크롤」을 골랐나

세 안 중 ③(자동 스크롤)을 고르고, 도착 규칙을 **「카드 머리를 nav 아래 84px」**로 정했습니다.

- **②(3열 아래 전폭 영역)를 기각한 이유**: 패널을 카드 밖으로 빼면 `aria-controls` 로 묶인
  머리–패널 관계가 끊기고, **동시 다중 펼침**(패널이 하나뿐인 영역이면 불가능)과
  「접힌 카드 = 옛 2층카드, 펼친 카드 = 옛 아코디언」 구조가 함께 무너집니다.
- **84px 은 새 값이 아닙니다** — 이 파일이 앵커 도착지에 이미 쓰는 값입니다. 다른 값을 쓰면
  한 페이지에 도착 높이가 두 종류가 됩니다.
- **`block:'center'` 를 버렸습니다** — 카드가 화면보다 높으면 머리까지 잘립니다.
  종전 `[data-timeline-open]` 경로가 그랬고(아래끝 y=965 > 900), 그 경로도 같은 함수로 모아
  **어디를 눌러도 같은 자리에 도착**하게 했습니다.

## 3. 지시 2 — 「파란 테두리」의 정체

계산값은 **이미 왼쪽 선 하나**였습니다. 문제는 `border-radius: 6px` 이었습니다 —
3px 짙은 왼쪽 변이 모서리 호를 타고 1px 연한 변으로 번지면서 좌상·좌하에 **짙은 갈고리**가
남고, 그 갈고리가 「둘러싸임 = 선택됨」을 만듭니다(4배율 캡처 육안 확인).

그래서 **테두리는 세 카드가 똑같이 1px `--line`** 으로 되돌리고, 표시는 **모서리에 닿지 않는
안쪽 막대**(위아래 10px 여백)로 그렸습니다. 위아래를 띄우는 것이 이 방식의 전부입니다 —
0 으로 붙이면 다시 테두리로 읽혀 같은 문제가 재발합니다.

> **지시 문면과 다르게 판단한 부분**: 「전체 테두리를 제거」 대신 1px 상자 테두리를 남겼습니다.
> 같은 지시가 정본으로 지목한 `.story-side.is-case` 가 **1px 상자를 그대로 두고 왼쪽 3px 을
> 더하는** 방식이고, `--bg` 위 `--bg` 카드라 상자를 없애면 경계 자체가 사라져 이 카드만
> 다른 종류로 읽히기 때문입니다(지금 문제를 반대 방향으로 되풀이). 목적인 「선택됨처럼
> 보이지 않게」는 갈고리 제거로 달성됩니다. **상자까지 없애길 원하시면 한 줄 변경입니다.**

## 4. 지시 3 — 캡처

| 카드 | 결과 |
|---|---|
| 수출 사전점검 | **변경 없음.** 이미 결과화면 캡처(`c03-result-detail.jpg`)를 갖고 있었습니다. `c03-result.jpg` 로 되돌리면 바로 위 03 신뢰와 한 화면 거리에 같은 그림이 두 번 납니다 |
| 바이어 확인 | `c03-result.jpg` 신규 배치 + 캡션 「이 결과화면 안에서 그대로 진행됩니다」 |
| 기한 관리 | **신규 자산** `timeline-map.jpg` — app.trops.kr 홈 「계약이 향하는 곳」 패널 실캡처 |

기한관리가 가장 큰 변화입니다. 종전에는 랜딩이 제품 정책(FR·AE 2개국 · 애니메이션 0 ·
점에 수치 0)을 **손으로 흉내 내고** 있었고, 제품이 바뀌면 조용히 갈라질 통로였습니다.
캡처는 그 화면 자체이므로 세 정책이 자동으로 지켜지고, 제품이 스스로 싣는 고지
(「이 지도는 예시이며 실제 계약이 아닙니다」)까지 함께 들어옵니다.

`.feat-map` · `.feat-map-note` · `.feat-pins` · `.feat-pin` · `.feat-pin::before` 를
마크업·CSS 양쪽에서 걷어냈습니다.

## 5. Check 단계가 잡아낸 것 (설계를 한 번 뒤집음)

**「접을 때는 스크롤하지 않는다」 → 「접을 때도 카드 머리는 지킨다」**

설계 전제(닫는 사람은 그 자리를 떠나려는 것이 아니다)가 실측에서 깨졌습니다.
전폭 카드가 접히며 3열 줄로 **돌아가면서 위로 올라가**, 방금 접은 카드 머리가
**y = −238 로 화면 밖**이 됐습니다. 무엇을 접었는지 알 수 없는 상태입니다.

기준은 다르게 뒀습니다 — **접기는 머리만, 펼침은 카드 전체**. 접기에 카드 전체를 요구하면
3열에서 옆 카드가 길 때 불필요하게 따라 움직입니다.

## 6. 검사 4건 갱신 — 전부 변이 검사로 확인

바꾼 검사가 「형식만 통과」하지 않는지 일부러 코드를 망가뜨려 확인했습니다.

| 검사 | 종전 → 지금 | 변이 결과 |
|---|---|---|
| `landing-emphasis-s10` E11 | `border-left` 존재 → `::before` 막대 + **모서리 여백 ≥6px** | 여백 0 / border-left 부활 → 둘 다 ❌ |
| `landing-flow-s9` 지도 정책 | 핀 2개 세기 → 실캡처 + 자리표시자 양쪽 0 | 핀 부활 → ❌ |
| `landing-flow-s9` 가짜 지도 | 자리표시자 유지 강제 → 셰브론 외 SVG 0 | `<svg>` 삽입 → ❌ |
| `landing-order-s9` O4-b | 파일 중복 무조건 금지 → **기본 노출 중복 금지 + 접힌 패널 허용 목록** | 허용목록 비움 → ❌ |

O4-b 완화는 사용자 승인 후 진행했습니다. 그 규칙이 지키려던 것은 주석에 적힌
「**한 화면 거리에** 같은 그림이 두 번 나지 않는다」이고, 접힌 패널 안 이미지는 클릭해야
보이므로 그 거리에 놓이지 않습니다. 허용은 **명시된 목록**에서만 통과시킵니다.

## 7. 기각한 가설

**`:focus-visible` 파란 링** — `.feat-btn` 이 카드를 꽉 채우므로 2px `--accent` outline 이
카드 전체를 감싼다고 의심했으나, 마우스 클릭 실측에서 `isFocusVisible: false`.
키보드 조작에서는 정상적으로 뜨며 **접근성 기능이라 손대지 않았습니다.**

**전용 바이어확인 캡처** — `/c/[token]/buyer`(화면 C-06)는 유효한 접수 토큰을 요구하고,
운영 DB 조회는 차단되어 있습니다. 데모 데이터를 운영 DB 에 쓰는 것은 승인 없이 할 일이
아니라고 판단해, 지시서가 미리 승인한 대체안을 썼습니다.
