## 2. 지시 1 — 탭이 스크롤 문제를 「고치는」 게 아니라 「없앤다」

| | 전 (s11 아코디언) | 후 (s12 탭) |
|---|---|---|
| 전환 시 스크롤 | 260ms 뒤 보정(`revealFeat`) | **0px · 보정 코드 자체가 없음** |
| 탭/카드 위치 | 재배치로 이동(접으면 `top=-238`) | **315px 불변** |
| 패널 가시율 1440×900 | 100 / 72.5 / 77% | **셋 다 한 화면**(아래끝 671·751·833 < 900) |
| 동시 다중 펼침 | 허용 | 정의상 하나 — 정책 폐기를 주석·검사에 기록 |

s11 이 스크롤로 쫓아다니던 이유는 **펼침이 줄을 재배치했기 때문**이었습니다. 탭은 패널
자리가 고정이라 그 일이 생기지 않습니다 — 지시하신 「스크롤 이슈 원천 차단」 그대로입니다.

**접근성**: roving tabindex(0/−1/−1), ←→↑↓·Home·End, 선택되지 않은 패널은 `[hidden]` 이라
감춘 버튼에 포커스가 들어가지 않습니다. **JS 가 죽어도** 상품 이름 3개 + 첫 상품 설명
전문(350자)이 보입니다 — 이름만 보이던 아코디언보다 낫습니다.

## 3. 기한관리 왼쪽선 — 제거로 판단했습니다

맡겨 주신 판단입니다. **제거**했습니다.

탭은 선택 상태를 스스로 표시합니다. 그 위에 굵은 선을 얹으면 s11 에서 걷어낸 혼동
(「선택됨처럼 보인다」)이 탭 안에서 그대로 되살아납니다.

다만 그 선이 지던 뜻 — **생애주기가 전 2 · 후 1 로 갈린다** — 은 지켰습니다:

| 대체물 | 효과 |
|---|---|
| 탭마다의 `.feat-meta` (거래 시작 전/전/후) | 옛 카드에서는 **접힌 상태에서만** 보이던 것이 **항상** 보임 |
| 탭 2↔3 의 빈 거터 | 3열 카드가 쓰던 트랙 구조를 그대로 승계 — 실측 16px vs **54px** |

즉 **선은 지우고 뜻은 남겼으며, 오히려 더 자주 보이게** 됐습니다.

## 4. 지시 2 — 캡처를 액자에 넣었습니다

| | 전 | 후 |
|---|---|---|
| 표시 폭 | 전폭(최대 1104px) | **560px** |
| 프레임 | 1px 테두리만 | 매트 여백 10px + 테두리 + 부드러운 그림자 |
| 캡션 | 이미지 밖 `<p>` (간격 16px, 큰 이미지에 묻힘) | **`<figcaption>` 액자 안 · 간격 0px** |

⛔ **브라우저 창 목업은 덧씌우지 않았습니다.** `c03-result.jpg` · `c03-result-detail.jpg` 는
신호등 + 주소창이 **이미 이미지 안에 찍혀** 있어서, 또 두르면 크롬이 두 겹이 됩니다.
대신 중립 매트 액자를 썼습니다 — 「액자에 넣은 참고물」로 읽히게.

패널을 **본문 왼쪽 / 캡처 오른쪽 두 열**로 나눈 것도 같은 목적이자, 패널을 낮춰
세 패널이 모두 한 화면에 들어오게 한 조건입니다.

## 5. Check 단계가 잡아낸 실제 결함 1건

**이미 발송된 메일의 앵커가 sticky nav 뒤에 깔렸습니다** — 실측 도착 위치 `top=0`.

`api/_notify.js` 가 만드는 `https://www.trops.kr/#feat-timeline` 이 결제확인 메일에 실려
이미 나가 있습니다. 세 가지를 함께 처리했습니다:

1. `id="feat-timeline"` 을 **항상 보이는 탭 버튼**에 둡니다. 패널에 두면 `[hidden]` 이라
   앵커가 도착할 대상이 없어집니다.
2. `scroll-margin-top: 84px` 을 **`.tabs`(줄)가 아니라 `.tab`(버튼)에** — 이 속성은
   **스크롤 목표가 된 요소 자신**에만 듣습니다. 줄에 걸었을 때 `top=0` 이었습니다.
3. **해시로 그 탭을 엽니다.** 브라우저는 앵커까지 데려다줄 뿐 열려 있는 것은 첫 탭이라,
   기한관리를 보러 온 사람에게 사전점검을 보여주게 됩니다.

이 결함들은 **화면이 깨지지 않아서** 눈으로는 안 보입니다. 실측 기준을 안 뒀으면 그대로
나갔을 항목입니다.
