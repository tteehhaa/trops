## 3. 금지를 푼 근거 — 어제 배치가 사유를 없앴습니다

이 자리에는 코드 주석과 검사 양쪽에 금지가 걸려 있었습니다.

### ① 사전점검 — 「**바로 다음** 「결」 섹션의 주 CTA 와 중복」

```
전:  [상품소개 탭]  →  [결 CTA · 비교해 보기(주)]        ← 한 화면에 둘이 함께 놓임
후:  [상품소개 탭]  →  [05 근거 · 527px]  →  [결 CTA]    ← 함께 놓이지 않음
```

`basis-split-s13` 이 그 사이에 근거 섹션을 넣으면서 **「바로 다음」이 아니게 됐습니다.**
금지의 문면이 아니라 **사유**가 소멸했으므로 금지도 함께 소멸합니다.

### ② 바이어확인 — 「죽은 클릭(눌러도 아무 일 없는 버튼)을 만들지 않는다」

이 사유는 **버튼에 갈 곳이 없을 때만** 성립합니다. 이 상품은 사전점검 **안에서**
진행되므로 갈 곳이 있고(`/precheck`), 버튼 바로 위 `.feat-note`
(「사전점검 결과화면에서 바로 확인하실 수 있습니다.」)가 그 사실을 이미 말합니다.

안내문은 **남깁니다** — 버튼만 남으면 「비교해 보기」가 왜 바이어확인 탭에 있는지
설명하는 문장이 사라집니다. 안내가 말하고, 버튼이 실행합니다.

## 4. 라벨을 새로 짓지 않은 이유

바이어확인 탭에 「상대방 확인해보기」 같은 전용 라벨을 지을 수도 있었지만 쓰지 않았습니다.

- **같은 목적지 = 같은 말.** 목적지가 같은데 라벨이 다르면 읽는 사람은 **다른 곳**으로
  갑니다. 지시도 「비교해 보기 누르면 가는 곳으로 **동일하게 취급**」이었습니다.
- **상품명을 버튼에 넣을 수 없습니다.** 「바이어 확인」·「수출 사전점검」은 상품소개 섹션
  안에서 **정확히 1회**만 나와야 합니다(`test/naming-consistency.test.js` — 한 상품 =
  한 번의 설명). 버튼에 넣으면 2회가 됩니다.
- 이 페이지는 이미 같은 라벨을 무게로 가르고 있었습니다 — HOW 하단의 `비교해 보기` 는
  2026-08-13 에 `btn-primary` → `btn-text` 로 강등된 **같은 문장**입니다.

기한관리만 라벨이 다른 이유는 **목적지가 다르기** 때문입니다(app.trops.kr · 별도 흐름).
