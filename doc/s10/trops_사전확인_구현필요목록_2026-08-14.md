# TROPS 「사전 확인」 종합 구현 필요 목록 (2026-08-14)

1단계(main_web 파트) 자체는 완료·라이브 배포됐고 결함이 없습니다. 이 목록은
그것과 별개로 — **설계서 v3에는 있었지만 구현계획서 v1의 12개 작업 목록으로
번역되지 않은 항목들**입니다. bkit이 빠뜨린 게 아니라, 작업 분해 단계에서
누락된 스펙입니다.

우선순위는 "근본 → 파생 → 독립 → 경미" 순입니다. 위쪽이 막히면 아래쪽도
못 붙입니다.

## A. 근본 — 이게 없으면 B가 불가능

### A-1. `intake_id` 역기입 (세션 ↔ 접수 연결)

- **현재 상태**: `/precheck?pre=<session_key>`는 hidden 필드까지만 심어짐.
  이 폼의 제출이 onSubmit에서 JSON 본문을 직접 조립하는 방식이라 hidden
  필드가 실제로는 전송되지 않음
- **필요한 것**: `api/intake.js`가 `pre` 파라미터(또는 hidden 필드값)를
  읽어 JSON 조립 시 함께 실어 보내고, trops_a 수신 쪽이 그 값을
  `precheck_prestep_session.intake_id`에 채워넣는 왕복
- **왜 근본인가**: 이게 없으면 "이 접수 건이 어느 사전확인 세션에서
  왔는지" 자체를 알 수 없음. B의 모든 항목이 이 연결에 의존함
- **레포**: main_web(`api/intake.js`) + trops_a(수신 로직)

## B. 파생 — §3-1 사후처리 (A-1이 먼저 있어야 의미 있음)

연결하는 코드가 없음.

## G. 추가 감사로 새로 발견 (2026-08-14) — 측정 인프라 전체가 빠짐

앞서 A~D는 "값은 저장되는데 개별 후속 로직이 안 붙었다"였습니다. 이번
감사로 드러난 건 그보다 큽니다 — **측정 인프라 자체가 통째로 없습니다.**

### G-1. 테이블이 사실상 write-only

`precheck_prestep_session`의 `id` 제외 12개 컬럼 중 **11개 전부**
(situation·experience·docs·completed_step·exited_via·cta_clicked·
referrer) 저장 코드만 있고 읽는 코드가 0건입니다. `app/api/prestep/
route.ts`는 POST만 있고 GET이 없습니다. 컬럼이 존재하는 이유(나중에
읽어서 계측한다) 자체가 지금은 성립하지 않습니다.

### G-2. §10 측정 쿼리 8개가 코드로 존재하지 않음

설계서가 "관리자 화면 없어도 DB 쿼리 8개로 다 나온다"고 스스로
전제했는데, **그 쿼리 자체가 구현계획서 §11 12개 작업 어디에도 배정된
적이 없습니다.** trops_a 전체(`lib/precheck-store/*`·`app/api/*`·
`app/admin/*`)에 SELECT/GROUP BY/집계 로직 0건. `app/admin`에
`prestep` 문자열 자체가 없어 2단계 착수 흔적조차 없습니다.

**이게 A(intake_id)·B(§3-1)보다 더 넓은 문제입니다.** A·B는 "특정 값을
못 씀"이지만, G는 "8개 지표 중 단 하나도 지금 이 순간 뽑을 방법이
없다"는 뜻입니다. 관리자 화면(2단계 작업13)을 만들 때 **화면과 쿼리를
동시에 새로 짜야** 합니다 — 지금 문서만 보면 "쿼리는 이미 있다"는
착시가 생깁니다.

### G-3. §6-2 분모 분할("접수전환율 = 서류 보유자 기준") 미구현

G-2와 같은 원인(쿼리 자체가 없음). 이게 없으면 설계서 §6-2가 명시적으로
경고한 사고 — 설계가 좋아져도 서류 없는 방문자가 분모에 섞여 숫자가
나빠 보이고, 그걸 롤백 신호로 오판하는 것 — 가 그대로 재현됩니다.

### G-4. `sales_contract`·`quote_pi` 비중 — 로드맵 수요 신호

설계서 §3-1이 "매매계약서·견적서 대조 상품을 언제 열지 판단하는 유일한
데이터 신호"라고 명시했는데, 이걸 만드는 작업이 §10 8개·§11 12개·
2단계 13·14번 어디에도 없습니다.

### G-5. (확인만) 크로스레포/인계 문구 — D11 외 새 항목 없음

설계서 전체 4곳(269·416·492·501행)을 grep — 전부 D11 하나만 가리킴.
음성 확인 완료, 추가 조치 불요.

## 종합 결론

데이터 적재 경로(스키마·저장·프록시·upsert)는 설계대로 완벽하지만,
**적재 이후가 통째로 비어 있습니다.** A(intake_id)가 가장 근본이고,
그 위에 B(사후처리 5건)와 G(측정 인프라 전체)가 나란히 파생됩니다.
G는 B보다 범위가 넓어서 — B는 5개 조건 각각을 붙이는 일이지만, G는
"측정 자체가 원천적으로 불가능한 상태"를 고치는 일입니다.

**다음 우선순위 제안**: G-2·G-3(측정 쿼리+분모분할)과 G-4(로드맵
수요신호)를 구현계획서 §11에 정식 작업 항목으로 추가할지 대표 결정
필요.
